# @deepseek-ai/dsh-client-authentication

[English](README.md) | 中文

浏览器认证能力拥有一条页面局部的续期链。`BrowserAuthentication` 在受保护插件加载前运行，轻量登录入口向其提供签名浏览器会话交换。外壳通过显式闭包把同一个运行实例交给 Cordis `BrowserAuthenticationService` Provider。消费者使用 `ctx.clientAuthentication`；其插件卸载时停止并排空该实例。

续期在半生命周期启动，并在窗口聚焦、标签页恢复可见及网络恢复时唤醒。每次交换有十秒的中止期限；瞬时失败采用上限为十秒的退避重试。凭据过期或明确的接入拒绝会使请求等待共享交换。单个请求取消只结束该调用方的等待。非敏感快照区分就绪、续期中、恢复中、需要刷新和已停止状态；显式免认证模式单独标识。

同源 `fetch` 只在 HTTP 401 携带 `x-dsh-authentication: required` 时重试一次，该标记由 Host 在业务分发前发出。未分类的 401、403、网络故障和执行结果不确定的写操作均不重放。一次性请求流不会被缓存或重放。恢复后再次收到明确拒绝时，需要手动刷新；服务器 sealed 或设备证明被拒绝时，需要重新认证或批准。任何恢复路径都不会自动刷新页面。Connection 的 XHR 上传载体使用同一接入与恢复服务，同时保留进度及取消能力。

启动阶段的交换回调必须响应 AbortSignal，并在 `stop()` 完成前结束。调用方在排空完成后才清除认证 Cookie。迟到请求结果不能恢复已经停止的认证。服务不会通过可观察状态暴露 Cookie、私钥或签名。

## 模型体验

无；浏览器接入不改变模型输入，也不停止正在运行的 Host agent（智能体）。

#### KV Cache 影响

无；不涉及提供方请求或上下文组装。

## 已知限制与暂缓事项

- 运行实例之外发生的浏览器 Cookie 变化在下一次受保护请求或连接检查时发现，不持续轮询。健康快照表示最近确认的状态，不保证下一次网络请求绝不会失败。
- 续期在每个页面内合并。标签页共享浏览器 Cookie，但各自拥有页面生命周期；没有跨标签页主节点选举或持久化出站消息队列。
