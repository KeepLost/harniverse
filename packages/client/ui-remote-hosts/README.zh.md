# `@deepseek-ai/dsh-client-ui-remote-hosts`

[English](README.md) | 中文

SSH 管理的远程 Harniverse 主机 Web 管理界面。它在现有设置、定时任务和会话管理界面旁边增加侧栏入口与中心视图；当前机器仍是工作区上下文，主机选择与连接操作由此页面负责。

页面使用生成的 `remoteHosts` Remote 契约，列出不含秘密的主机记录，在保存前检测连通性，通过 Host 凭据提供方保存密码或私钥，连接和断开不会停止远程进程，并配置明确的远端来源到本地目标的反向映射。提交后不会再次渲染私钥值或口令。已连接的主机行会以 `dshRemoteHost` 打开新的页面；原始本地页面继续作为管理权威。

中心视图沿用定时任务页面的骨架（固定头部，含已连接计数摘要与操作区，其下为滚动的卡片列表；添加主机的编辑器是右侧抽屉，按 Escape 关闭）。密钥登录默认走宿主本地路径，由 `remoteHosts.keyFilePicker()` 路由：`native` 组合由 Host 打开以操作者 `~/.ssh` 为起始目录的原生单文件选择器（`remoteHosts.pickKeyFile()`）；`browse` 组合打开密钥目录流槽位（`remoteHosts.keyDirectoryFlow`）的对话框，其中列出的是 Host 所在机器上的目录——绝不是浏览器所在机器——确认后填充路径的目录部分，操作者在获得焦点的路径输入框里补全文件名；`absent`（或探针失败）则保留手动输入路径。保存的凭据就是路径本身，由 Host 在使用时读取文件，同样受 64 KiB 上限约束。一个共享的密码输入框承载登录密码或私钥口令，随所选登录方式切换。勾选「手动粘贴密钥内容」后互斥切换——粘贴可用、路径输入与拾取按钮禁用——取消勾选则相反。封闭的 `KEY_*` 线上错误码会以本地化文案呈现，而不是原始消息。

## 模型体验

本包不贡献模型可见提示词、工具、事件或请求字段。主机操作始终是经过认证的 Remote 操作。

#### KV Cache 影响

没有直接影响。中心视图不会改变模型请求前缀。

## 已知限制与延期事项

- 表单创建主机记录并管理其生命周期；修改已保存记录需要删除并重新创建，从而避免已连接会话静默改变指纹或凭据引用。
- 保存前必须通过一次连通性检测；任何对被检测地址、端口、用户或凭据的修改都会使其失效，因此表单保存的始终是登录已被证实的指纹，而不是操作者手输的值。此后主机密钥一旦变化，会表现为检测失败，而不会被静默接受。
- 反向映射在连接前配置，连接完成后才启用；请求路由和重连状态由传输协调器负责。
- 远程页面要求本地协调器保持主机连接；关闭页面不会停止远程进程，而断开协调器后远程页面会等待本地主机重新连接。
