# `@deepseek-ai/dsh-client-ui-skin`

[English](README.md) | 中文

“外观”设置中的皮肤相关界面：皮肤图库、强调色、壁纸、玻璃材质与面板不透明度、皮肤包，以及把壁纸或皮肤自带渐变画在界面框架后面的外壳背景。它是纯浏览器端插件，建立在 [`@deepseek-ai/dsh-host-skin-library`](../../host/skin-library/README.md) 的 `skinLibrary` Remote（`ctx.remote.skinLibrary`）、该包注册的 `ui-skin` 设置命名空间（`ctx.settingsScope`）以及 [`@deepseek-ai/dsh-client-ui-theme`](../ui-theme/README.md) 的主题服务（`ctx.theme`）之上；node 一侧不注册任何 host 行为。插件自己不带全局样式表，只设置主题所有者已经声明的 token。

## 组装

```yaml
# host row (the Remote this plugin drives) is owned by the web-app bundle
# browser row
- id: ui-skin
  name: '@deepseek-ai/dsh-client-ui-skin'
```

插件注入 `slots`、`locale`、`theme`、`remote`、`skinLibrary` 命名空间服务（没有挂载皮肤库的 host 永远不会激活它）以及 `settingsScope`。它向 [ui-layout](../ui-layout/README.md) 声明的 `shell.backdrop` 列表槽位贡献一个条目（id `skin`，order `0`），并向 ui-theme 的“外观”分区声明的 `settings.appearance.item` 列表槽位贡献五行，id 与 order 如下：

| id | order | 行 |
| --- | --- | --- |
| `skins` | 30 | 皮肤图库 |
| `accent` | 40 | 强调色 |
| `wallpaper` | 50 | 壁纸 |
| `material` | 60 | 材质与不透明度 |
| `packs` | 70 | 皮肤包 |

ui-theme 自己的行（`appearance` 10、字号 20）排在它们之前；其中 `appearance` 行就是颜色模式（跟随系统／浅色／深色），所以图库不再重复这三项。这五行与它们所依附的槽位声明一同安装、一同回滚。

## 行为

- **皮肤即主题。** 皮肤库列出的每个皮肤都注册为一个主题：id 为 `skin:<id>`，带有它的配色方案与 token，因此选择皮肤就是 `ctx.theme.setTheme('skin:<id>')`，由现有的呈现器应用。只设置了 `--dsw-accent` 的皮肤，其 `--dsw-accent-hover` 与 `--dsw-accent-soft` 由它派生。皮肤库会在打开“外观”分区时、本插件自己上传／导入／删除之后、以及连接重新建立时重新读取；只有定义发生变化的皮肤才会重新注册，所以无关的刷新不会拆掉正在使用的皮肤。读取失败时保留上一份可用的皮肤库并记录一条警告；首次读取之前皮肤库为空，图库不显示任何卡片，只有 ui-theme 的“颜色模式”行可选。皮肤对应的偏好值是 `skin:<id>`；若该主题未注册（皮肤已离开皮肤库，或皮肤库尚未读取），偏好会被保留，主题服务在皮肤重新注册之前渲染系统配色；只有通过本插件删除当前使用的皮肤包时，才会显式把偏好切回 `system`。
- **客户端复核。** Host 会校验皮肤包，但远程机器的皮肤库只有那台机器那么可信，所以皮肤的 token 在进入文档之前会再检查一遍：名称必须是 `--dsw-*` 自定义属性，值必须是颜色（`#rgb`、`#rgba`、`#rrggbb`、`#rrggbbaa`，带三个或四个数值参数的 `rgb()`／`rgba()`／`hsl()`／`hsla()`，或 `transparent`）。其余一律不写入：`url()`、`var()`、`calc()`、`color-mix()`、命名颜色和声明截断都不行。渐变图层与卡片预览使用同一套检查。
- **单一覆盖层。** 插件只维护一个 `ctx.theme.overrideTokens('ui-skin', …)` 覆盖层，由设置、当前主题与操作系统偏好重新计算，只有内容变化时才重新应用。
  - *强调色。* 保存的强调色会同时设置 `--dsw-accent`、`--dsw-accent-hover` 与 `--dsw-accent-soft`。悬停色在浅色调色板上向白色移动 20%，在深色调色板上向黑色移动 20%，与基础调色板已有的方向一致；柔和色是强调色以 18% 叠在其后所绘内容之上（`color-mix(in srgb, <accent> 18%, transparent)`），因此在纯色表面和壁纸上都清晰可读。
  - *半透明表面。* 有背景绘制时，`--dsw-surface-pane` 与 `--dsw-surface-sidebar` 变为各自所替代的别名按面板不透明度混合，`--dsw-surface-composer` 按输入框不透明度，`--dsw-surface-popover` 按菜单不透明度，形式都是 `color-mix(in srgb, var(<alias>) N%, transparent)`；表面绝不读取它自己。没有背景时不覆盖任何东西，面板保持不透明。
  - *材质。* 有背景时，`frosted` 把三个 `--dsw-material-*-filter` token 设为 `blur(16px) saturate(1.4)`，`liquid` 设为 `blur(28px) saturate(1.8) brightness(1.05)`；`off` 不设置。
  - *无障碍。* 当系统要求减少透明效果（`prefers-reduced-transparency: reduce`）或更高对比度（`prefers-contrast: more`）时，无论保存了什么，背景都会关闭、表面保持不透明、材质保持关闭。插件监听这两个查询并实时响应；材质控件会说明被停用的原因。
- **背景。** `skin` 条目优先绘制所选壁纸（皮肤库仍持有它时）：图像取自 `readWallpaper` 返回字节生成的对象 URL，使用 `background-size: cover`，应用保存的模糊值，再叠一层把图像向基础色拉近 30% 的遮罩以保证可读性；否则绘制当前皮肤自带的渐变，由类型化构造器把结构化图层转换为 CSS 渐变（数值被限幅、颜色经过检查，有任何不可用内容的图层整层丢弃）。两者都没有时不渲染任何内容。壁纸 URL 按哈希引用计数：图库缩略图与背景共用同一个 URL，最后一个持有者负责撤销；在最后一个持有者离开之后才完成的读取不会留下 URL。
- **皮肤图库。** 一组单选卡片，皮肤库中的每个皮肤一张——内置皮肤按皮肤库顺序在前，导入的皮肤包在后；每张卡片都带有一个由该皮肤自己的 token（以及渐变）绘制的迷你预览。图库里没有“跟随系统”、“浅色”、“深色”卡片：颜色模式是它上方 ui-theme 自己的那一行。该行的说明文字会告诉用户：选择皮肤会替换上方的颜色模式，再次选择颜色模式即可回到默认外观。只有持久化的偏好正是该皮肤时，对应卡片才处于选中状态；偏好为跟随系统、浅色或深色时没有卡片被选中，第一张卡片是 Tab 停靠点。整组是一个 Tab 停靠点，使用漫游 tabindex；方向键移动并选中，在两端循环，Home 与 End 跳到首尾。皮肤库为空时（仍在读取或无法读取）不渲染这一组，读取失败时该行会说明。选择对所有主体都有效；在设置无法保存的地方，该行会说明这次选择只在页面保持打开期间有效。
- **强调色。** 十二个预设色块、一个原生颜色输入框（尚未保存强调色时显示当前皮肤自带的强调色），以及恢复为当前皮肤自带强调色的重置。
- **壁纸。** 上传（PNG、JPEG、WebP；读取任何字节之前先按 Host 的大小上限检查文件，再以 base64 经 `putWallpaper` 发送）、以缩略图网格展示的最近壁纸（选用、删除）、回到“不使用壁纸”的入口，以及只在选中壁纸时才可用的模糊滑块。新上传的壁纸会自动选中；删除当前壁纸会清除选择。拒绝原因以类型化形式返回并用中文显示：图片无法识别、超过大小上限、类型不受支持、壁纸数量已达上限。
- **材质。** 一个分段控件（关闭／磨砂／液态玻璃）与三个不透明度滑块（面板与侧栏 40–100%、输入框 40–100%、菜单 60–100%）。没有背景时，该行会说明不透明度与材质需要壁纸或带背景的皮肤；在减少透明效果或高对比度下，所有控件被停用并显示原因。
- **皮肤包。** 导入 `harniverse.skin` 格式的 `.json` 文件（按 Host 的皮肤包大小上限检查，作为文本读取，经 `importPack` 发送）；被拒绝时逐条列出 Host 返回的问题。已导入的皮肤包带删除按钮列出，删除当前选中的皮肤包会先把偏好切回“跟随系统”。磁盘上未通过校验的皮肤包文件会连同原因一并列出。*导出当前皮肤* 会在浏览器中依据皮肤库里的定义构造皮肤包并下载；内置皮肤导出为 `<id>-copy` 下可编辑的副本（内置 id 是保留的），导入的皮肤包则以自己的 id 导出，重新导入即为替换。
- **权限。** 读取皮肤库只需要观察权限；保存设置、上传、导入与删除需要管理权限。各行始终显示已保存的状态；当 Host 文档只读、`ui-skin` 命名空间未对外开放、或皮肤 Remote 写入因权限不足被拒绝（锁定到插件重新加载为止）时，写入控件会被停用并给出简短提示。
- **编辑。** 拖动滑块或选取颜色会立即暂存，控件与实时预览随之变化；输入静止 200 毫秒后按顺序写入，所以一次拖动只产生一次写入，而不是几十次。
- **无障碍。** 卡片与材质分段是带标签的单选组中的 radio；色块是带标签分组中的切换按钮；滑块、文件输入与颜色输入是带可见标签的原生控件；提示使用 `role="note"`，结果使用 `role="status"`，失败使用 `role="alert"`；焦点环来自 token。

## 状态与接线

一个 `SkinController` 拥有各界面所依赖的全部来源（皮肤库、设置作用域、主题服务、产品语言与环境查询），并通过一个裸可观察对象发布唯一一份不可变的 `SkinView`，由渲染器在每个注册的 `hooks` 隔间里绑定为 `useSkin(selector)`。切片在内容变化之前保持引用不变，因此针对某个切片的选择器不会被另一个切片的变化唤醒。控制器同时负责注册皮肤主题、应用覆盖层，并实现各行以普通回调形式接收的操作（选择主题、暂存设置、上传或删除壁纸、导入或删除皮肤包、导出、获取或释放壁纸 URL）。组件从不接触 `ctx`。`/client` 入口只导出 `apply`、`inject` 和类型。

## 模型体验

无。皮肤只改变浏览器的外观；皮肤设置的任何内容都不会进入模型请求。

#### KV Cache 影响

无；该包既不组装也不发送提供方请求。

## 已知限制与暂缓事项

- **强调色上的文字可能对比不足** —— `--dsw-alias-label-primary-foreground`（强调色与墨色填充上的文字颜色）由主题决定，而不是由强调色决定，所以很浅或很深的用户强调色会让按钮文字难以辨认。该行不会对此给出警告。
- **壁纸只能来自上传** —— 远程 URL 壁纸、自定义字体与密度不在范围内；Host 只保存本地图片字节。
- **渐变尺寸假定背景与视口等大** —— 径向图层的大小是较大视口边的百分比（`vmax`），只有背景铺满视口时才与之相符。
- **缩略图读取完整图片** —— 每张最近壁纸在该行首次显示时都按完整尺寸读取（最大为 Host 上限），该行关闭时撤销；没有服务端缩略图。
- **拒绝是靠 Remote 失败的代码与消息识别的** —— 浏览器并不知道自己的权限，所以被拒绝的皮肤 Remote 写入是从失败结果中识别的（`forbidden`、`authorization-denied`、`unauthorized`，或消息中指明缺少某个 `harniverse.*` 权限）。被拒绝的设置写入则完全不会被报告；设置作用域会重新加载 Host 的值，控件随之回到该值。
- **皮肤库没有推送通道** —— 它在打开“外观”分区时、本插件自己写入之后以及重连时读取；别的浏览器所做的导入会在下一次这类时机出现。
- **皮肤与颜色模式是同一个选择** —— 主题偏好只保存一个值，所以选择颜色模式会丢掉当前皮肤，之前选过的颜色模式也不会在皮肤之下被记住；皮肤自己决定配色方案。
- **没有导航图标** —— 插件不拥有设置分区，因此不向 `settings.nav.icon` 注册任何内容。
