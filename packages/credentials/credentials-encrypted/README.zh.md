# dsh-credentials-encrypted

[English](README.md) | 中文

面向远程运行时的加密 [CredentialProvider](../credentials/README.md)，模型与搜索凭据以本地客户端为权威来源。默认导出为 `EncryptedCredentialProvider`，仅注册一个 `ctx.credentials` 实例。包同时具名导出该类及 `EncryptedCredentialControl` 接口，不创建第二个服务实例或上下文键。

## 配置

| 字段 | 默认值 | 含义 |
|---|---|---|
| `path` | `<harness home>/.credentials.encrypted.json` | 加密快照的存储位置。 |
| `dshHome` | `$DSH_HOME` 或 `~/.dsh` | 未指定 `path` 时使用的 Harness 主目录。 |

配置只包含文件位置。协调器通过经过身份验证和授权的通道在运行时提供加密密钥。加密密钥和凭据值均不从远程环境变量或插件配置加载。

## 运行时控制

协调器声明注入 `credentials`，并通过 `instanceof EncryptedCredentialProvider` 缩窄 `ctx.credentials` 的类型。同一个对象同时实现凭据服务及其控制方法：

| 方法 | 契约 |
|---|---|
| `unlock(key: string): Promise<void>` | 接收以规范、无填充 base64url 编码的 32 个密码学随机字节（43 个字符）。验证并加载现有文件；文件不存在时启动空会话。 |
| `replace(values: Record<string, string>): Promise<void>` | 持久化替换整个快照。省略的引用会被删除，`{}` 删除全部凭据。要求提供方已解锁。 |
| `status(): { locked: boolean }` | 立即返回可用状态，不暴露密钥材料或凭据元数据。 |
| `lock(): Promise<void>` | 立即将自身持有的密钥缓冲区覆零、清除凭据值、取消排队操作，并等待尚未结束的文件 I/O。允许重复调用，包括销毁之后。 |

这些方法是受信任的进程内控制接口，不是身份验证端点。协调器必须先验证远程请求的身份和权限，再调用控制方法，并避免记录请求体。`set` 和 `unset` 始终以本地权威来源错误拒绝远程修改。`describe` 始终返回 `writable: false`，在锁定或销毁后返回 `configured: false`。解锁后的解析结果使用来源 `encrypted`，忽略环境中的凭据。

启动时仅注册处于锁定状态的服务，不打开存储文件，也不等待密钥，使身份验证和引导服务可以就绪。锁定时 `resolve` 立即拒绝，不等待重新连接。进程重启后，协调器必须重新连接并解锁，模型和搜索操作才能解析凭据。销毁会永久锁定实例，此后解锁、替换、解析和写入均被拒绝。

使用当前密钥重复解锁是幂等操作。使用不同密钥解锁会拒绝，并保留当前会话。锁定后，密钥错误、文件不可读、载荷损坏或版本不受支持，均以同一条经过脱敏的 `credentials-encrypted: unlock failed` 错误拒绝，提供方保持锁定。文件不存在时，首次成功替换才会建立持久化的密钥关联。

## 持久化与通知

版本 1 的 JSON 封装仅包含 `version`、`iv`、`tag` 和 `ciphertext`。AES-256-GCM 每次替换均生成新的 12 字节随机 IV，使用 16 字节认证标签，以及绑定包和版本的附加认证数据。凭据值和引用名称均位于密文内。解密先完成认证，再解析凭据；非法封装和快照均拒绝使用。

每次提交先在同目录中以独占方式创建随机命名的 `0600` 临时文件，写入并同步文件、关闭句柄、原子重命名，然后在 POSIX 上同步所在目录。直接父目录以 `0700` 创建；已有父目录若含组或其他用户的权限，则拒绝写入。新建目录的目录项会在提交前逐级同步到已有的祖先目录。读取时拒绝非普通文件、最后一个路径分量为符号链接的文件，以及 POSIX 上权限过宽的文件。Windows 不提供这些 POSIX 权限检查或目录同步保证。

重命名之前写入失败，会保留最近提交的文件和内存快照，不发送事件。重命名成功后若目录同步或关闭失败，则持久性不确定：替换操作拒绝，提供方锁定，不发送事件。重新连接并解锁会先读取实际文件，再允许重试。

替换成功时先发布完整快照，再针对每个新增、改变或删除的引用发送一次 `credentials/updated`。值未变时不发送事件，即使替换生成了新密文。解锁和锁定不发送持久化更新事件。监听器失败遵循[凭据服务契约](../credentials/README.md)；不变量失败会在变更引用通知完成后继续抛出。

解锁和替换按接收顺序串行执行，最多允许 16 个尚未完成的操作，超出时以繁忙错误拒绝。锁定立即使排队操作失效。已经开始的密文重命名可能在锁定或销毁期间完成，替换承诺也可能成功，但不能再次发布凭据值或事件。`lock` 和销毁只有在这些 I/O 结束后才会完成。

## 边界

快照最多包含 1,024 个条目，引用必须为 POSIX 风格标识符，最多 128 个 ASCII 字符；凭据值为非空字符串，每个值最多 65,536 个 UTF-8 字节。包含 JSON 转义和结构信息的完整明文序列化结果最多 1,048,576 字节。包含封装的加密文件最多 1,500,000 字节；读取最多分配和消费该上限加一个字节。接收时会复制并验证输入记录，调用方之后的修改不能改变排队中的提交内容。

## 模型体验

模型与搜索提供方间接使用解析出的值为请求授权。本包不添加提示文本、工具模式、模型可见输出或 token 开销。提供方锁定时，这些操作无法解析凭据。

#### KV 缓存影响

不直接使缓存失效；凭据材料不会进入请求前缀。

## 已知限制与后续工作

- 每份文件由一个提供方进程独占管理。不提供跨进程写入协调或文件监听；外部修改需锁定后重新解锁才能加载。
- 本包保护静态存储中的凭据。获授权的插件或能检查已解锁运行时的进程仍可取得秘密。调用方负责管理 `resolve` 返回的副本。
- JavaScript 字符串、调用方持有的 base64url 密钥和原生密码学实现中的副本无法可靠覆写。锁定和销毁会显式覆零提供方持有的密钥缓冲区，并释放值引用，但无法撤回已返回的值。
- 不提供自动密钥恢复、轮换或经过认证的修订历史。丢失本地密钥后，已有文件无法读取；有效的旧密文可能被重放，直到本地权威来源再次替换。
- 存储调用依赖操作系统的 I/O 完成。队列长度和文件大小有界，但停滞的文件系统仍可能延迟锁定或销毁完成。
