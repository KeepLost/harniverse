# `@deepseek-ai/dsh-base`

English | [中文](README.zh.md)

The shared dsh core as a profile bundle: [`cordis.patch.yml`](cordis.patch.yml) inserts every base plugin row — model adapters, the shared [`agent-default-model`](../../core/agent-default-model/README.md) selection, tools, persistence, policy, settings/credentials, telemetry, and host-level subagent providers — over the empty profile root, as the first layer of every profile's `dsh.profile.bundles` list. The multi-provider `llm-pi-ai` adapter is enabled and exposes configured catalog or custom routes; the native `llm-deepseek` adapter is an optional disabled row. Codex and Claude Code providers load dormant; Agent Presets independently decide whether their agent contributes either model-facing delegation tool. Later bundle layers (e.g. [`dsh-web-app`](../web-app/README.md)) and the user's profile `cordis.patch.yml` override these rows by id; a patch replaces a row's whole `config`, so mode-specific values live in mode bundles, not here. The package has no runtime API; the profile composer resolves the patch through the `dsh.bundle.patch` manifest field, never through code.

The patch gates both shell stacks on `$DSH_SHELL_BACKEND` (published by app boot from the `shell-backend:` settings section; an unset value falls back to the platform split — pwsh on win32, bash elsewhere), so exactly one shell stack mounts per start. The execution world follows the same shape one layer deeper: `$DSH_EXEC_WORLD` (from the `exec-world:` settings section, degraded to `local` when the VM provider probe is unhealthy) symmetrically gates the capability families — `subprocess`/`sandbox`/`fs-sandbox` for the host-local world versus `vm`/`subprocess-vm`/`fs-vm`/`sandbox-vm` for the QEMU microvm world. Under the vm world an unset `$DSH_PERMISSION_MODE` resolves to `danger-full-access` (the world boundary is the sandbox), and the policy fallback root becomes the in-world `/workspace`; an explicitly pinned confined mode composes real in-guest Landlock enforcement through `sandbox-vm` (fail-closed when the guest reports no backend). Guest egress rides the same world: the `vm` row opens the egress surface (`egress: ask`), and every dial a spawn's process makes through its in-guest SOCKS5 proxy asks the initiator's session an approval card — unattributed, refused, or providerless dials deny by default. The permission surface otherwise stays exactly as on POSIX: `sandbox`/`sandbox-policy` enforce the file-effect policy through the Windows ACL restricted-token runner (the win32 chain of `dsh-sandbox-local` → `@deepseek-ai/dsh-sandbox-windows-acl`), the permission switcher and the approval service run unchanged, and `fs-sandbox` keeps fencing `ctx.fs` writes — mounting `dsh-fs-local` alongside it would double-register `ctx.fs` and fail the load. A Windows host that prefers the unconfined local pwsh executor or full access overrides these rows through its profile or home `cordis.patch.yml` (the bash-restore recipe must be complete: disable `pwsh-sandbox`/`tool-pwsh` AND re-enable `bash-sandbox`/`tool-bash` — both executor families register the same `bash` service, so an incomplete recipe fails loud at load).

The row set and its rationale are documented inline in the patch file; the [generated composition graph](../../../apps/cli/composition.md) renders it.

The shipped Web rows mount the `ctx.web` service, the official search providers `deepseek-search-api`, `exa`, `perplexity`, `tavily`, `brave`, `kagi`, and `cloudflare`, the aggregate `firecrawl` Search/Scrape provider, and the anonymous `http` fetch provider. `deepseek-search-api` and `http` are the selected defaults; each provider resolves its own credential reference per operation. The `tool-web` row sets both `search` and `fetch` to `false`, so the shared base contributes neither `web_search` nor `web_fetch` to any model request. A deployment may replace the complete `tool-web` config to enable the tools after choosing its routing policy; `$DSH_WEB_SEARCH_PROVIDER`, `$DSH_WEB_FETCH_PROVIDER`, and the browser's live Web defaults select the provider without adding fallback behavior. Search and fetch provider registrations remain independently selectable, while Firecrawl owns both capabilities under one provider id.

## Model Experience

Indirectly, through the inserted rows: this bundle selects the shipped persona-less prompt base, tool set, and multi-provider adapter that mode bundles specialize, and contributes no model-visible text of its own.

#### KV Cache effect

None directly; each inserted row's package owns its effect.

## Known Limitations and Deferred Work

- **A patch replaces whole row configs** — profile overrides must restate every field a row keeps; there is no deep-merge layer.
- **Claude's SDK platform CLI remains in the Profile install closure** — the base bundle depends on the Claude provider, whose production path resolves the host `claude`; removing the SDK's unused optional payload is deferred to the product installation-closure follow-up.
- **The Windows temp grant is a private per-session subdirectory** — `workspace-write` confines writes to the workspace plus the session's own temp subdirectory (`<temp>\dsh-<hash>`, TMP/TEMP rewritten for confined children); `read-only` grants nothing. See `@deepseek-ai/dsh-sandbox-windows-acl`.
