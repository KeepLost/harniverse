# @deepseek-ai/dsh-attachment-local

[English](README.md) | 中文

这是 [`@deepseek-ai/dsh-attachment`](../attachment) 的私有本地实现。对象存放在 `<DSH_HOME>/attachments/v1/objects/<sha256-prefix>/<sha256>`，并通过不透明的 `sha256:` 标识符寻址。每个进程都会通过将每个祖先目录项逐级同步到文件系统根目录，为某个 home 一次性证明其持久性，因此绝不会把另一个进程已经创建但尚未同步的目录误认为安全边界。随后，写入过程使用私有暂存目录、仅所有者可访问的文件、经过同步的临时文件、原子且排他的硬链接发布，并对发布路径执行目录同步（适用于 POSIX；Windows 依赖文件系统元数据日志），确保已报告的引用能够在崩溃后继续存在。写入准入与读取都会完整解码光栅图片，之后才接受其格式和尺寸；读取还会重新校验摘要和已记录的元数据。字节和像素限制属于写入时的准入策略，因此后续收紧限制不会导致已经接纳的历史记录变得不可读。

`DSH_HOME` 按共享路径策略解析：显式配置、`$DSH_HOME`，最后是 `~/.dsh`。会话日志只包含引用和经过校验的元数据，绝不包含这个宿主路径。`readImage` 会把可选取消信号传入文件系统读取、在校验前后观察该信号，并保留取消语义，而不会将其包装成 `ATTACHMENT_READ_FAILED`。

本地后端通过 `<DSH_HOME>/attachments/v1/request-images` 下的确定性提供方请求字节实现 `readImageRequest`。请求版本保持宽高比且不会放大，并受选定的像素和字节策略限制。已经符合策略的 PNG、JPEG 和 WebP 可以直接复用；其他情况使用有界的 JPEG 或 WebP 编码。旁路文件仅所有者可访问，以原子方式发布，在复用前重新校验，并与持久附件对象分离。

通用文件经 seam 的文件面共享同一对象树：`saveFile` 在 `maxFileBytes` 准入上限（默认 100 MiB）内逐字节原样存储——不嗅探、不规范化格式，调用方声明的媒体类型仅作记录——`readFile` 复验摘要与字节长度。`publishFileHandle` 幂等地把已存对象硬链接到 `<DSH_HOME>/attachments/v1/links/<sha8>-<文件名>` 并将共享 inode 标记为只读（0o444）：模型读取的句柄路径在对象树日后重整时仍然有效，重复发布已存在的链接是空操作。无可用的显示名时回退为 `<sha8>.bin`。

## 模型体验

该包通过重启和 fork 后对历史用户图片与结构化模型图片输出的持久回放间接影响模型。通用文件只以确定性句柄文本（文件名、字节数、sha256 前缀、只读链接路径）到达模型；字节本身绝不进入模型请求。

#### KV 缓存影响

除发起请求的适配器所持有的图片块外，不产生其他影响。

## 已知限制与待完成工作

- 对象会无限期保留；基于引用的垃圾回收尚未实现。
- 本地后端假定宿主与提供方适配器共享同一个文件系统服务。
- 动图 GIF 元数据从逻辑屏幕校验；帧级解码策略由提供方所有。
- 通用文件的媒体类型是调用方声明、仅作记录；存储不从字节验证它们。
