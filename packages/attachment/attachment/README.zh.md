# @deepseek-ai/dsh-attachment

[English](README.md) | 中文

持久附件服务边界。`ctx.attachments` 校验并以原子方式提交不可变图片字节，随后返回可序列化的 `ImageAttachmentRef`；消费方绝不会在会话事件中持久保存浏览器路径、对象 URL、提供方 URL 或 base64。

未发送的输入区图片仍是由浏览器持有的临时草稿。`admitEncodedImages` 解码采用规范 base64 的命令信封，并将其交给 `saveImages`；批量操作会在首次持久写入前应用当前部署的数量、总字节数、媒体类型和单图校验，再按提交顺序返回引用。`validateImage` 运行相同的单图准入策略但不执行持久化，`saveImage` 会在发布任何模型可见的会话事件前提交每张已接受的图片，`readImage` 则根据已记录的元数据校验内容寻址对象。调用方可以取消 `readImage`；实现会在后端读取与校验工作的边界观察取消，并保留取消语义，而不会将其转换为存储失败。

`readImageRequest` 是一个可选的附加提供方操作，用于生成有界且临时的模型请求图片版本。其策略控制总像素和编码字节；派生版本携带独立的 `ImageVariantId`，不会改变持久引用、源字节或会话事件。没有实现请求投影的提供方会以 `ATTACHMENT_PROJECTION_UNSUPPORTED` 拒绝，因此现有附件消费方保持原有行为。

## 模型体验

该包通过角色无关的核心 `ImageBlock`，以及解析其持久引用的提供方适配器，间接影响模型。

#### KV 缓存影响

添加图片会改变提供方请求，因此会使受影响的请求后缀失效。

## 已知限制与待完成工作

- 第一版仅接受 PNG、JPEG、WebP 和 GIF。
- 保留策略与垃圾回收尚未实现，因为恢复和 fork 后的会话可能共享不可变对象。
- 通用文件、音频、视频和持久的未发送草稿需要单独的生命周期与提供方契约。
