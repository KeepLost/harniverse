# Agent Note: Voice input — speech seam, local SenseVoice, cloud chain, composer microphone

Status: implemented

English | [中文](2026-10-03-voice-input.zh.md)

Scope: `packages/speech/*`, `packages/host/apiproxy`, `packages/client/ui-voice-input`, `packages/bundle/base`, `packages/bundle/web-app`, `apps/desktop`

## Problem

UPSTREAM-ABSORPTION-REVIEW.md row X15: Harniverse had no voice input. The upstream harness ships an experimental speech stack (`api-speech-to-text`, `speech-to-text`, `speech-to-text-sensevoice`, `client-ui-voice-input`) built on its typert Remote protocol and a worker-process runtime — none of which Harniverse's apiproxy/composition model can absorb as-is.

## Decision

- **Speech seam as a Service Definition** (`@deepseek-ai/dsh-speech`, `ctx.speech`). One concrete registry service holds `registerRecognizer(id, recognizer)` (effect-scoped, duplicate ids fail loud), resolved preferences pushed by the settings bridge, `resolve()` answering the paired recognizer or a `disabled`/`unknown` refusal, and `prepare`/`transcribe` over it. The `SpeechRecognizer` contract keeps the task's exact minimal face — `transcribe({ wav: Uint8Array; language?: string }, signal?) → { text: string }` — plus optional `inspect`/`prepare` readiness. Canonical WAV intake validation is exported from the seam package, parameterized (`sampleRate`/`channels` defaults 16 kHz mono, `maxDurationSeconds`), replacing upstream's fixed constants.
- **Local SenseVoice provider** (`@deepseek-ai/dsh-speech-sensevoice`). Asset pins copied verbatim from the upstream release (model int8/fp32, tokens, Silero VAD: URLs, exact bytes, sha256) into `src/assets.ts`. Assets live under `$DSH_HOME/speech/sensevoice/` with a written `manifest.json` recording the accepted pins; `inspect` fails when files or manifest drift. Downloads stream into unique `.part` files, hash while streaming, and publish atomically; the ordered source chain races HEAD probes over `https://huggingface.co` and `https://hf-mirror.com` with download fallback; HTTP/network failures fall to the next source, integrity failures abort. `fetch` is injectable for suites. The `sherpa-onnx-node` binding (pinned 1.13.8, bundling ONNX Runtime) loads lazily at the first `transcribe` — preparation never loads native code.
- **Deviation from upstream: in-process inference.** Upstream isolates the binding in a managed worker process; Harniverse loads it in-process (lazy require) because the X15 decision line names only the lazy binding and the subprocess seam is not part of this batch. Recorded as the package's top known limitation; promotion is deferred until field evidence demands it.
- **OpenAI-compatible cloud provider** (`@deepseek-ai/dsh-speech-openai`). Upstream has none, so the chain is designed here: `endpoints` (official `api.openai.com/v1` first; overlays append gateways) walked per request — transport failures, timeouts, and 408/429/5xx fall through; a definitive 4xx fails the chain immediately (shared key ⇒ repeated semantics). The API key and language come from the settings namespace; a missing key fails before any bytes leave.
- **Settings namespace persistence** (`@deepseek-ai/dsh-speech-settings`). The `speech` namespace (`applies: 'live'`, composition `base`) holds `recognizer` (`'off'` default), `language`, `pushToTalkKey`, `modelVariant` (`'int8'` default), and `apiKey` (`role('secret')`, redacted on every wire surface). Registering pushes the resolved value into `ctx.speech`, and `scope.watch` follows every commit — the bridge rides the plugin fiber.
- **Remote with a Harniverse capability** (apiproxy). `speech.transcribe` (`{ wavBase64, language? } → { text }`, `harniverse.operate`, mutate) validates canonical base64, a 4 MiB byte ceiling, and `validateWav(…, 120s)` before the seam sees audio; refusals map to `speech-unavailable` (seam absent / selection off / unknown id) and `speech-transcription-failed`. `speech.prepare` (`{} → SpeechPrepareView`, `harniverse.operate`, mutate) joins the resolved recognizer's preparation and answers the settled observation. Wire registration follows the X05 `jobs.follow` chain exactly: `api/speech.ts` + `api/speech.schema.ts` + two `RpcMethodMap` rows + fetch handler routes + `IApiClient.speech` + the in-process fixture dispatch. `'speech'` joins `WEB_SETTINGS_NAMESPACES` so the settings surfaces reach the namespace.
- **Composer microphone + Settings section** (`@deepseek-ai/dsh-client-ui-voice-input`, one package owning both seats). The mic button sits in `conversation.input.left`: click records (getUserMedia + MediaRecorder), a second click stops and re-encodes entirely in the browser (AudioContext decode → downmix → linear resample → canonical PCM16 WAV) before `speech.transcribe`; transcripts insert through the scoped `slash/input-insert-text` event with the draft-revision CAS (a miss offers manual insertion). Push-to-talk holds the configured key. Not-ready guidance is locale-owned (zh/en): recognizer off, permission denied, unsupported capture, empty transcript. The Settings → Voice input section (a `settings.section` entry) edits the namespace through the shared settings scope and drives `speech.prepare` with its settled status.
- **Desktop main-frame microphone permission.** The deny-all `setPermissionRequestHandler`/`setPermissionCheckHandler` now grant `'media'` only while the window shows the connected Host's loopback Web origin; the renderer shell and every other origin stay denied. `build.mac.extendInfo` gains `NSMicrophoneUsageDescription`. Windows needs no manifest entry for desktop-app microphone access.
- **Shipped composition.** The base bundle mounts `speech`, `speech-settings`, `speech-sensevoice` (`dataRoot: !!js dshHomePath('speech')`), and `speech-openai`; the web-app bundle mounts `ui-voice-input` with its three registration surfaces (tsconfig.client.json reference, `dsh.client` row, bundle dependency).
- **Third-party notices.** `sherpa-onnx-node` (Apache-2.0) enters the runtime table through the manifest; the generator gains a "Downloaded model assets" section disclosing the pinned SenseVoice release (Apache-2.0), Silero VAD (MIT), and the bundled ONNX Runtime (MIT).

## Alternatives considered

- Absorbing the upstream typert `SpeechController` Remote: rejected — Harniverse remotes are apiproxy RPC rows under `harniverse.*` capabilities; a parallel Remote protocol would bypass the authentication contract.
- A second settings provider keyed by recognizer: rejected — one namespace with `'off'` keeps selection, cloud key, and push-to-talk in one hot-reloaded document the existing settings UI already mirrors.
- Recording straight to webm/opus on the wire: rejected — the seam contract and the Host validator admit one canonical form (16 kHz mono PCM16 WAV), so the browser owns the transcode.

## Consequences

Voice input is a plugin-native capability: the seam, both providers, the preference bridge, and the browser seats each mount or unmount independently, and the wire surface declares its `harniverse.operate` capability like every other business route. First local use downloads ~227 MB (INT8) into `$DSH_HOME/speech/sensevoice` with pinned sha256 verification; without preparation the local recognizer answers `unprepared` and the UI guides. The in-process native binding remains the standing risk recorded above.
