# Agent Note: 保留 TODO 可见性并恢复模型上下文压力

Status: implemented

[English](2026-08-27-todo-and-context-recovery.md) | 中文

本说明在 TODO 生命周期决定上部分取代[下一轮次清空 todo 计划](2026-07-28-todo-plan-clears-on-next-turn.md)；原说明中的压缩事务理由仍然有效。

## Problem

Web TODO dock 使用的投影会在 `turn/start` 清空，因此会话停止后，未完成工作的唯一便捷进度视图可能消失。同时，请求压力检查发生在当前输入追加之前，模型容量也没有扣除配置的输出预留。大请求可能以 400 抵达提供方；后续恢复如果与轮次边界重叠，手动 `/compact` 还会报告误导性的 busy 错误。

## Decision

`todos` 投影现在跨越轮次边界按最后一次写入覆盖。只要列表非空，无论项目状态如何都会保持可见，直到新的 `todo/write` 替换它，或 host 没有该投影状态。

自动压缩在 `agent/request` 边界再次检查当前持久化输入的压力。达到阈值后，在发起请求前执行压缩；如果表层已经被替换，agent loop 会重新构建派生消息。同一个请求边界会把 `maxTokens` 限制在上下文剩余容量内。如果提供方仍返回规范的上下文溢出错误，恢复 listener 会先将显式输出上限减半并重试，再使用强制压缩兜底。

手动 `compactNow()` 会等待正在运行的 agent 收敛，并允许命令 signal 取消等待，然后才预留空闲维护接纳。因此 busy 结果只代表真实的压缩锁或非法开放轮次，而不是停止操作期间正常的短暂收敛窗口。

## Alternatives considered

- **每个新轮次都清空 TODO**——会在停止会话最需要查看未完成工作时丢失它。
- **只在提供方返回 400 后裁剪**——仍会暴露本可避免的提供方错误，并延迟压力压缩。
- **由 UI 或命令层执行压缩**——重复模型/上下文所有权，并绕过持久化压缩 seam。
- **允许手动和自动压缩并发**——可能破坏串行的表层替换事务。

## Consequences

TODO 面板现在作为常驻进度视图保留，直到写入更新列表。请求准备可以在 adapter 收到请求前等待压缩；成功替换后，loop 会刷新模型可见的历史。输出上限在单次操作内降低，并在 assistant 成功响应或 agent 进入 idle 后重置。手动命令可以等待正在运行的轮次，而不是返回短暂的 busy；真实持久化锁仍保持 fail-closed。

覆盖范围包括跨 `turn/start` 的投影与组装 Web TODO 保留、请求边界输出裁剪、当前输入压力压缩、上下文溢出重试，以及等待 agent idle 的手动压缩。
