# Agent Note: 侧边栏批量归档选择器

Status: implemented

[English](2026-11-01-sidebar-batch-archive-picker.md) | 中文

## 问题

归档此前只有逐行手势：每个会话都要单独走一遍行菜单，收拾一个有大量已完成会话的工作区意味着把“打开菜单 → 归档会话”重复 N 次。归档查看器已经提供归档会话的批量**删除**，但反向的批量——把多个活跃会话一次性移入归档——并不存在。头部也只携带一个归档入口（查看归档会话），其图标是归档箱，而永久删除恰恰住在那里，图标并未表达这一点。

## 决策

- 第三个头部队面**批量归档**通过一个按钮进入，位置在*添加工作区*与*查看归档会话*之间。它镜像归档查看器的模式形态：激活时拥有分区标题与列表主体（搜索、视图选项、添加按钮隐藏），两个归档面互斥——每个模式的入口按钮在对方内部隐藏。折叠栏（rail）态与查看器同样可达：点击展开侧边栏并翻转 `aria-pressed`。
- `BatchArchivePanel` 列出活跃账目（注册表归档集尚未吞掉的每一个会话，最新在前），带逐行复选框与全选开关（全选同时承担取消全选）。确认时通过行菜单同款 `ctx.workspaces.archiveSession` **顺序**归档每个勾选会话——没有新的宿主表面，没有批量 RPC。
- **活跃会话明确报错，仅此而已。** `SESSION_ACTIVE` 拒绝在面板警示区按会话渲染一行（“{name} 仍有进行中的工作，未归档”）；批量路径绝不打开“停止并归档”对话框，也绝不带 `stopActivity` 重试。停止运行中的工作是有意的逐会话手术——跨多会话静默杀掉回合、后台任务与子代理的批量确认，正是本流程拒绝成为的破坏性手势。其他拒绝渲染为 `name: message`；成功者在归档集回声落地时消失。
- 图标拆分：选择器拿归档箱（归档这个动作）；归档查看器拿回收站（永久删除住在那里）。`IconTrashOutline16` 来自共享 primitives——没有新资产。

## 备选方案

**行菜单弹出模态对话框。** 侧边栏保持静态，但把手势与它作用的列表割裂，且归档查看器已经为这种形状的面确立了就地模式先例。

**客户端预过滤活跃会话。** 客户端的 `running` 标志是展示投影；宿主的 `SESSION_ACTIVE` 回答才是权威（含定时任务与排队工作）。预过滤会与宿主静默不一致，并藏起流程承诺的显式拒绝——行内改为展示“进行中”提示，由宿主的拒绝来定夺。

**一个批量 RPC。** 宿主侧 `sessions/archiveMany` 会为无行为收益的 N 次已签约方法顺序调用增加线上表面、宿主记账与回放语义；N 是侧边栏规模，不是服务器规模。

## 后果

- 组装浏览器金样新增头部按钮（*Add workspace* 与 *View archived sessions* 之间的 `button "Archive sessions"`）；两个 lifecycle-chrome 金样已随本变更在 `DSH_SNAPSHOT=refresh` 下刷新。
- 验证：workspace-browser 套件五个新用例（含全选/取消全选与逐行开关的批量流、活跃显式拒绝与批量同伴成功并存、非 Error 拒绝的逐字渲染、模式互斥与折叠栏可达、空态）；`BatchArchivePanel.tsx` 每文件 100% 覆盖；`pnpm run test:gui`；`pnpm run build`；改动文件 oxlint；金样刷新后的 web e2e 回放。
- 关系：行菜单归档及其“停止并归档”确认、归档查看器的只读管理与批量删除（[2026-08-24 会话归档生命周期](../architecture/2026-08-24-session-archive-lifecycle.md)）保有逐会话路径并拥有 `stopActivity` 重试；本 Note 只拥有批量入口手势。
