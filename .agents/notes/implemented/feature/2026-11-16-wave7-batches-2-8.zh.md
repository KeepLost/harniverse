## Problem

七个已接受的 wave-7 行各关闭一处我们持有的接缝:核心 `Session` 没有整批追加,导入方只能逐事件发布、没有原子边界;已存密钥 UI 把存储值换进输入框(一次揭示就泄漏),且首击键即删除凭据;markdown 围栏不可扩展——插件无法装饰或替换某语言的渲染;工作区文件搜索用 JS 走树,忽略语义劣于平台;会话无法在配置根之外授权可写目录(策略面没有按活跃会话的注册);我们 pin 的 pi-ai 0.87.1 不可达 Gemini,尽管协议实现就在 pin 内;chat.deepseek.com 导出没有进入持久 Session 的导入路径。

## Decision

- **批 2 —— 元组数组 `append`(行 11,`dca88eb4b2`)。** `Session.append(inputs)` 接受 `readonly SessionEventInput[]`:`prepareBatch` 在任何成员进入日志前校验并快照全部成员,然后一个发布信封按序投递;`currentBatchPublication` 为 `session/event` 观察者点名在途成员。不变量伴件跨批折叠 `projectTrace`(虚拟折叠;序号断点重定基)并断言编号重启。单事件热路径不动。
- **批 3 —— 已存密钥 UX(行 13,`30ddeba2e7`)。** `CredentialInfo` 增加提供方生成的 `masked` 预览(前缀 + 尾四位可见;八字符及以上隐藏中段);`describe` 批量以 `CREDENTIALS_DESCRIBE_MAX_REFS=64` 封顶。`ApiKeyInput` 仅以掩码为占位、Backspace/Delete 暂存移除、显示已存密钥期间阻断 copy/cut;`ProviderEditor` 保存按 unset → settings → set 顺序应用;提示三态(file / 仅 env 名 / 缺席)。
- **批 4 —— markdown 围栏 HOC 槽位(行 16,`f08b32d2d2`)。** `conversation.chat.markdown.fence` 是首个 keyed HOC 槽位:注册以 `kind: 'hoc'` 声明并携带 entry key;`composeHocLayers` 按 host 的 entryKey 过滤,各语言图层链式叠加而不独占围栏。内置 `math` 与 `diff`/`patch` 图层随行——diff 围栏把 git/uni diff 解析为文件分节、按节语言 token 化,经 `MarkdownDelegateFenceInfo`/`renderCode` 委派;每次出现都崩溃回落到普通代码块。
- **批 5 —— 经打包 ripgrep 的文件搜索(行 ⑤,`e880faf8bd`)。** 新 `packages/util/ripgrep` 持有 `resolveRgPath`(平台包、Electron unpacked 路径或单文件 sidecar——无系统回退)、`spawnRipgrep`(`--no-config` 前置,`RIPGREP_CONFIG_PATH` 无法注入预处理器)与 `readRipgrepLines`(有界流式、提前停止)。`searchWorkspaceFiles` 经 subprocess 提供方运行 `rg --files --sort=path --null`:`.gitignore`/`.ignore` 原生生效、隐藏文件默认跳过、预算恰好填满即报 `truncated`(更多文件从未被询问)。失败归入新错误码 `workspace-search-failed`。
- **批 6 —— 会话可写目录(行 17,`006a8cc891`)。** `sandboxPolicy.registerWritableRoot(session, directory)` 是 WeakMap 承载的逐会话 effect:解析时取活跃注册与配置根的并集,释放只影响后续操作,保留进程的执行器沿用进程启动时的授权。Windows 维持 owner 拒绝的边界——额外目录仅经 fs `write`/`edit` 工具检查授权;无 SID、无 ACL 变更。
- **批 7 —— Gemini 协议(行 7 方案 A,`6f92b48689`)。** `PROTOCOLS` 在 pin 的 pi-ai 0.87.1 上增加 `google-generative-ai`;发现走 `GET /v1beta/models`(`pageSize=1000`、`x-goog-api-key`),保留 `generateContent` 能力模型并剥 `models/` 前缀。`protocol-rules` 要求密钥并把推理锁定为 minimal/low/medium/high——无 Off。自定义提供方表单与模型能力视图接入该选项。
- **批 8 —— DeepSeek 聊天导入(行 14,`1c98af9367`)。** `session-import` 增加附加入口 `settleConverted`(标记 `deepseek-chat-v3`,lineage = 网站会话 id,内容派生身份,保留源工件,无 tmpdir 依赖)。新 `packages/host/deepseek-chat-import` 服务 `harniverse.operate` 门控的 NDJSON 上传路由(预算 1000 会话 / 512 MiB 归档 / 256 MiB 条目 / 80 B 标题;单一导入槽位;fflate ZIP 内存解析)并流式回报 progress/outcome 行。会话导入设置区新增导出 ZIP 入口流式上传;导入按内容身份去重——重复导入同一归档按冲突处理,绝不重复落盘。

## Alternatives considered

**为 Gemini 迁移 pi-ai 到 1.3.0。** 带触发记录地拒绝:1.x 重写 `llm-pi-ai` 所包裹的适配器面;方案 A 保持 pin 并自读原生模型列表。

**官方的 Windows SID/ACL 写授权路线。** Owner 拒绝进程提供方拥有的账户变更;额外目录保持文件工具检查边界。

**单文件 mock server 测 Gemini。** 0.87.1 google 适配器忽略自定义 fetch 选项,套件改为以 `@google/genai` 直连钉住的协议契约。

**整包移植官方导入包。** 其依赖面(事件词汇、tool-result 块、附件服务)与我们的不同;按模块适配,并以我们的 conversation/archive/upload 套件钉住官方 ZIP 形状。

**全局可写根注册表。** 以活跃 Session 身份为键的 effect-scoped WeakMap 让授权与生命周期同真(释放即停后续操作),全局注册表需要手工失效。

**扩展 JS 走树而非采用 ripgrep。** 忽略语义、预算与提前终止在打包二进制中已经存在;走树与平台树视图的分歧正是缺陷所在。

**每批一个 PR。** Owner 指示批 2–8 作为单个开放的 dev→master PR;批内提交保持可审序列。

## Consequences

- 批量追加给导入方一个原子发布:被拒成员在日志变更前拒绝整批,观察者可经 `currentBatchPublication` 区分成员。
- 已存密钥不再渲染其值;移除暂存至 Save 应用(unset 先于 settings),误击键不再删除凭据。
- 围栏图层成为插件领地:第三方图层可装饰或替换任意语言的围栏渲染,每次出现均崩溃隔离。
- 工作区搜索原生遵守工作树忽略文件——此行为变化记录于此:被 `.gitignore` 忽略的文件不再可搜,与模型自身所见一致。
- 会话可在其生命周期内授予额外可写根;部署保持其配置并集。
- Gemini 成为 `llm-pi-ai` 上首个非 DeepSeek 协议;推理暴露为四档,永无关闭。
- 聊天导出入库为普通 Session 并保留源;重复导入按设计冲突。
