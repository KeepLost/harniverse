# Agent Note:面向模型的 peer 工具

状态:已实现

中文 | [English](2026-11-19-peer-tool.md)

## 问题

配对(PR #324)与委派 Remote(PR #325)让已配对实例只能经 `dsh peer` CLI 触达:接受侧运行真实会话,但发起侧的模型没有任何通路。本子系统声明的作用——一个实例的*模型*委派到另一个 home——需要在既有配对通道之上增加面向模型的表面,而不扩宽协议。

## 决策

发布一个工具包 `dsh-tool-peer`,作为 `dsh-peer-client` 的纯消费方:工具拥有面向模型的 schema、目标解析、预算与渲染;证明、Grant 传输与 direct/SSH 拨号留在客户端库。具体:

- 单个工具(`peer`,名称可配置),参数 `target`(显示名或精确 instance id——id 优先于歧义名)、`prompt`(客户端限制 32768 字符,镜像主机侧校验)、可选 `session` 续聊、可选 `timeoutMs`。预算钳制在 1000–900000 ms,单次调用传输超时上限 120000 ms,对应 CLI 的 `boundCallTimeout`/`settleBudget` 组合。
- 目标可达性复用配对边界:没有 allowlist 配置。属主配对即批准目标,接受实例的 `PeerSurface` 字段仍在彼端约束每个 Remote 族;ToolRestriction 与所有一方工具一样按会话决定工具的存在性。
- 超预算仍在运行的回合返回 `state: 'running'` 与点名 session id 的续查引导,而不是阻塞模型的轮次;结束原因非 `completed` 的结算回合与每个封闭 peer 原因都映射为点名原因的工具错误。这两个选择让面向模型的契约对 peer 上发生的事保持诚实。
- CLI 的传输拨号移入 `dsh-peer-client`,成为 `withPeerOrigin`/`withPeerTransport`,工具与 `dsh peer` 共享同一实现;SSH 服务经 `ctx.get('remoteHostSsh')` 解析,对没有该服务的组合保持可选。

## 备选方案

- **专用 peer allowlist `Config`** —— 否决:配对本身已是属主批准的边界,接受实例的 `PeerSurface` 在彼端门控每个 Remote 族,ToolRestriction 按会话决定工具存在性;第二份名单只会重复该边界而不新增执行点。
- **第二个 `peer_sessions` 列表工具** —— 推迟:枚举是 CLI 已拥有的低频操作员工作;模型经续聊触达自己的会话,出现消费方时再交付列表工具。
- **长阻塞到结算完成** —— 否决:工具调用把父轮次占住一刻钟会饿死循环;有界预算加续查引导保持轮次响应,并成为 outbox 的提交路径。

## 放弃了什么

- 异步回执与结算推送:工具在预算内阻塞、由模型再问;发起方 outbox 里程碑负责排队投递与结果回推。
- 中止传播:父步骤中止不取消进行中的 peer 调用;单次调用传输超时约束等待时长,取消随会话化活跃通道到来。
- `peer_sessions` 列表工具:枚举留在 CLI;模型经续聊触达自己的会话。

## 后果

CLI 的传输拨号现在位于 `dsh-peer-client`(`withPeerOrigin`/`withPeerTransport`),配对通道的每个未来消费方共享同一拨号实现与校验;runner 失去私有副本,传输故障也不再带 `peer-runner:` 消息前缀。`peer` 工具面向模型的描述、参数文本与渲染字符串由 ACP 快照夹具钉定——改动其中任何一个都会按设计翻动夹具。预算钳制镜像 CLI 的 `boundCallTimeout`/`settleBudget` 组合,工具与 CLI 对超时语义永远一致。
