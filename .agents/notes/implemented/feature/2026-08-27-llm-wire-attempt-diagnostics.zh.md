# Agent Note：基于会话索引的 LLM 网络尝试诊断

状态：已实现

[English](2026-08-27-llm-wire-attempt-diagnostics.md) | 中文

## 问题

Session 日志保存对话、请求标头快照、规范化流分片和最终错误，但没有标识一次实际网络尝试所使用的适配器参数及提供方响应事实。因此，日志可以显示提供方或网关失败，却无法证明具体是哪一次传输尝试产生了它。

## 决策

LLM seam 在 `GenerateOptions` 上定义仅限运行时使用的网络回调字段。agent loop 提供一个 exchange id，并为每次适配器尝试追加一条 `llm/wire-attempt` 事件，引用请求标头序号、路由上下文序号、历史截点、轮次和步骤。事件保存协议、提供方、模型、端点、方法、请求字节数、规范化的非秘密 fingerprint、非上下文请求参数、选定的响应诊断 header、状态、耗时、结果和归一化错误事实。

两个已交付的网络适配器都在传输边界报告。pi-ai 适配器使用最终 payload 回调；当 pi-ai 没有暴露 HTTP 响应回调时，从 SDK 的状态行错误中恢复 HTTP 状态和提供方消息。direct DeepSeek 适配器记录每次 fetch，包括内部的过期文件 fallback 请求。

事件有意不保留完整请求体或响应体。消息、系统文本和工具只由 append-only Session 日志负责。回放结合引用的 Session 状态和网络参数，先比较重新生成的请求 fingerprint，再比较提供方状态和错误事实。

fingerprint 会规范化对象 key 顺序，且不是凭据 hash。带凭据的请求 key 会从保留的参数投影中排除。响应 header 会缩减为状态、请求／速率限制、内容、服务器和计时相关诊断字段。

## 后果

每次 agent 网络尝试增加一条小型日志事件，并执行一次轻量的进程内 fingerprint。成功和失败请求使用相同的请求侧记录形状；失败只额外增加归一化结果事实。正常 assistant 输出仍由已有的 `assistant/chunk` 和 `assistant/message` 事件表示，因此不会重复保存流式响应或对话历史。

当前回调仅限运行时使用；不提供观察器的独立手工 LLM 调用不会产生记录。若进程在适配器报告尝试前崩溃，该在途调用不会留下网络事件；崩溃完整网络捕获不属于本决策。

## 备选方案

否决持久化完整请求体和响应体，因为 Session 日志已经负责对话以及成功响应内容，而本次回放目标只是提供方状态和错误。否决不引用 Session 序号的独立网络日志，因为它会重复上下文，并且无法明确实际使用的历史位置。否决只在失败时保存请求，因为它会产生不对称行为，使成功与失败请求的比较变得不可靠。
