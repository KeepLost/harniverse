# Agent Note：ACP 内容传递 —— 图像、上下文计量、文档计划、跨重开的标题 —— 以及一个预设中的多个 agent

Status: implemented

[English](2026-11-28-acp-content-passage-and-several-agents.md) | 中文

## Problem

[ACP 模式](2026-11-27-acp-sign-in-session-binding-and-agent-state.md)在该人与外部 agent 之间只传递文本，并且一个预设只绑定一个 agent。该人附加的截图永远到不了 agent；agent 的某个工具读到的图像从对话记录中被丢弃；agent 的上下文计量从客户端核心到达后被抛弃；agent 以文档形式保存的计划不予展示；会话重新打开之后 agent 报告的标题不被应用；在两个 agent 之间选择意味着两份预设副本。

## Decision

**图像经由附件接缝双向传递。** [`@deepseek-ai/dsh-agent-acp`](../../../../packages/acp/agent-acp/README.md)把该人消息中的每张图像从 `ctx.attachments` 读回，作为图像块在文本之后按撰写顺序发送；客户端核心只把图像块发给握手允诺了图像 prompt 的 agent，否则在任何内容发出前拒绝该回合。驱动器不让这种拒绝发生：不接收图像的 agent、没有存储的组合，或无法读回的已存图像，都会让该图像留在原处，同时一条通知指明它及原因，回合继续进行。agent 发来的图像在写入之前经同一接缝存储 —— 它流式发来的作为其文本之后的一个块，工具调用报告的位于该调用结果之内 —— 因此对话像渲染任何附件一样从日志渲染它；存储无法保存的图像成为一段说明原因的文本注释。每张图像都在内容装配之前读取或存储，因此装配本身是同步的，而在其回合结束前被中断的片段保留其文本，不保留任何图像。

**上下文计量是 agent 词表中的一条记录。** ACP 的 `usage_update` 不是一次模型调用的 token 计数：它说的是 agent 在上下文中持有多少 token、它的窗口有多大，以及迄今的会话费用。把它放到 `assistant/message.usage` 上会把它当作 token 计费。因此 [`@deepseek-ai/dsh-agent`](../../../../packages/core/agent/README.md)声明只记入日志的 `agent/context` 记录 —— `used`、可选的 `size`、可选的 `cost` —— 由保留自己上下文的步骤驱动器写入，模型循环从不写入。token 计量器的 `contextPressure` 折叠把它当作自成一类的用量采样读取：`used` 锚定分子，`size` 锚定分母，因此输入框的占用环显示的是外部 agent 的真实占用。驱动器为每次不同的报告写入一条记录，且只写入范围内的整数。

**文档计划以其文本展示。** 计划为 Markdown 的 `plan_update` 没有可折叠进待办列表的条目列表；客户端核心把它规范化为 `plan-document`，驱动器把它展示为一条通知，携带全文及它所在的文件，每段不同的文本展示一次。它的移除不动待办列表，因为它从未喂给该列表。

**已应用的标题记录在重命名旁边。** 标题服务以同一方式存储每个被接受的标题，因此在内存里记住自己上一个标题的驱动器在重开后失去这份记忆，继而把现有标题当成该人的。驱动器现在在应用某个标题的重命名之后立即追加只记入日志的 `acp/title`；一个现有的标题，恰好当它既不是上次记录的那个、也不是空缺时，才是该人自己的。

**多个 agent 共享一个预设。** `agents` 指明一行可驱动的 agent，每个都带有单 agent 形式所取的启动字段；`default` 指明会话启动时运行的那一个。`/acp-agent` 列出它们并切换接下来各条消息运行的 agent；运行中的回合拒绝该切换，不同的 agent 使用属于它自己的进程。绑定记录本就指明了作出它的启动方式，因此下一条消息在所选 agent 仍持有它早先在本会话中打开的外部会话时重新接入该会话，否则打开一个新会话。这个选择不是一条新记录：重新打开的会话继续使用其最新的自有绑定所指明的 agent，也就是它上次交谈的那一个。

## Alternatives considered

**把 `usage_update` 映射到 `TokenUsage`。** 统计行和会话总计会把上下文 token 显示为已计费输入，而逐次调用的缓存字段又没有来源。一条说明 agent 所言的记录，由唯一以其为事实的显示来读取，把计费与占用分开。

**让 agent-acp 拥有私有的 `acp/usage` 事件并让 token 计量器读取它。** 计量器将不得不了解一个可选插件的事件。这条记录描述任何保留自己上下文的步骤驱动器，因此它属于驱动器接缝已经声明的词表。

**从文档的复选框派生待办条目。** 这是对某一种 Markdown 惯例的猜测，并且把一个事实放进两个家。文本被完整展示，待办列表仍是条目列表的。

**为标题服务提供一个由插件供给标题的 API。** 它为一个调用者拓宽核心服务，并且需要服务只为一个生成器保留的提供者槽位。一条由驱动器拥有、只被驱动器读取的记录，回答了它唯一的问题：站着的是谁的标题。

**注册一个 `generate` 返回 agent 标题的会话标题提供者。** 服务按自己的节奏、从该人的消息调用提供者，而不是在 agent 报告时调用。一个返回它最后听到的内容的提供者，就是那条记录加上更多机关。

**在创建会话时、在创建对话框里选择 agent。** 它需要会话创建 UI 中一个按预设的贡献点，而它并不存在。被驱动会话上的一条命令以零客户端改动到达同样的选择；对话框仍是后续事项。

**把选择保存在一条新的只记日志的事件里。** 会话自有日志的最新绑定已经说明它上次与哪个 agent 交谈，而这正是重新打开的会话应当继续使用的选择。

## Consequences

图像能到达接收图像的 agent，从 agent 的工具回到对话中，并在无法传递时向该人指明；输入框的环显示外部 agent 的上下文占用，`/acp` 把它与会话费用一并打印；文档计划与 agent 之后的标题可见；一个预设可以承载一个人在其间交替的每个 agent。

在只增策略下新增了三条记录 —— agent 词表中的 `agent/context`，以及 `acp/session` 旁边的 `acp/title` —— 并为它们重新生成了持久化目录与会话契约摘要。`SESSION_FORMAT_VERSION` 保持为 `0`。遇到它们却不认识它们的读取者会拒绝该日志，一如它对待每个它不认识的必需事件。

token 计量器的 `contextPressure` 单元升到 `stateVersion` 5，因此此前写入的持久化投影缓存会重新折叠一次。

agent 流式发来的图像排在其文本之后，与到达顺序无关；音频在两个方向上都不传递；文档计划不按 Markdown 渲染；agent 的选择只在 harness 进程内有效。各项均见于其所属的 README。

## Required verification

客户端核心针对其内存 agent 覆盖图像能力门控、文档计划与带类型的费用。驱动器通过真实工厂、针对真实子进程中的脚本 agent、在挂载本地附件存储的条件下覆盖：图像作为已存字节被转发、图像留在原处的三种方式及各自的通知、存储无法读回的图像、流式与工具报告的图像被存储并由其引用的块装配、存储无法保存的图像的注释、被中断的片段、每次不同报告一条上下文记录且范围外的计数被丢弃、`/acp` 的那一行、文档计划展示一次及其移除、该人的重命名在 agent 首个标题前后都保留、重新打开的会话接受 agent 之后的标题、默认 agent、一次切换、重新接入它回到的那个 agent、重开之后的继续、回合进行中被拒绝的切换，以及具名形式的启动错误。一个无密钥的 Loader 组合复制随发布的预设并挂载附件存储，驱动一个回合，其中该人的图像到达 agent，而 agent 工具报告的图像进入日志。token 计量器覆盖该折叠的四条路径。改动的源文件达到 100% 覆盖率。

本批次没有运行真实适配器：完成这项工作的地方没有安装任何适配器，而各适配器在线路上的图像与计量行为在此处仅从协议 schema 得知。`DSH_ACP_REAL` 仍是运行它们的方式。
