# Agent Note: 手机竖屏头部图标与宿主本地链接分流

Status: implemented

[English](2026-10-12-phone-header-icons-and-local-link-routing.md) | 中文

## 问题

两条移动端 Web 的反馈一起到达。竖屏下，会话头部的两颗功能胶囊——"Session 日志"与"工作区"——各自占据最小宽度 111px 的整文字药丸，两颗合计吃掉 390px 标题行的 230px，而这一行还要为框架的悬浮侧边栏入口让出 56px 缺口，面包屑被挤得只剩碎屑。

assistant 正文链接的打开方式同样不加分辨：默认的 `linkDestination: panel` 只要在组合进了宿主浏览器面板，就把每次普通左键都交给它，于是读者在自己设备上完全打得开的公网目的地也绕道宿主机；而面板存在的真正理由——从 harness 宿主机的网络位置到达宿主本地开发服务器或内网地址——并没有说明哪些链接配得上它。

## 决策

按形态收缩胶囊，按目的地权威路由每条链接。

两颗按钮在所有宽形态下保留文字药丸；在框架唯一的断点刻度（`data-viewport='phone'`，与其他竖屏让步选用的同一选择器）下各自收缩为裸 32×32 图标方块，文字隐藏、圆角收成半圆。Session 日志按钮补上显式 `aria-label` 与 `title`，图标方块因此保有可访问名称与悬停提示；工作区按钮本就带着 `aria-label`。

链接路由现在先分类目的地再询问面板：主机名是回环（`localhost`、`*.localhost`、`127/8`、`0/8`、`::1`）、内网网段（`10/8`、`172.16/12`、`192.168/16`、`169.254/16`、`fc00::/7`、`fe80::/10`）或页面自身的 harness 源站的 URL，在外壳组合了面板时交给宿主浏览器；其余一律拒绝接过、交还锚点，由其寻常的新标签页行为在读者正使用的浏览器中打开。`device` 偏好仍然拒绝一切——这是宿主机没有浏览器程序时的显式逃生口；面板分节缺失时同样拒绝，回退次序未变。分类器是一对纯函数（以页面主机名为取值的 `isHostLocalHostname`，读取 DOM 源站的 `isHostLocalUrl`），落在 `ui-conversation` 豁免于文件级门禁的 client 半区，带独立 spec；设置行的 `panel` 选项改名为"自动区分"，描述写明这一分流。

## 验证

`pnpm run test:gui` 绿（466 文件、6875 通过）。新增 `host-local-link.client.spec.ts` 覆盖分类器每个分支；`apply-inject.client.spec.tsx` 现在证明宿主本地链接进面板、公网链接留给读者、`device` 压过本地性、存储的偏好同样拒绝。`link-destination-row.client.spec.tsx` 断言新文案。被门禁触碰的文件（`HeaderAction.tsx`、`conversation-settings.ts`）保持语句/分支/函数/行 100% 覆盖。markdown-inline-code-links web e2e 保持其回环种子链接进面板，并把设置菜单选择器迁到改名后的选项。390×844 的 agent-browser 实机通过：两颗胶囊渲染为图标方块，标题行收回了空间。

## 考虑过的备选方案

用按钮自己的 `@media` 查询收缩胶囊会复制框架已发布的断点刻度；所有其他竖屏让步都选在 `data-viewport` 上，两颗按钮因此加入同一模式。保留全文只缩小字号被否决：药丸宽度由标签文字而非字形驱动，标题行仍会被吃掉。

路由方面，为 `panel` 偏好增加第三个 `auto` 值被否决：自动分流是唯一有人要的行为，持久化 schema 保持不动，而想把一切留在自己设备上的读者已有 `device`。把分类放进 markdown 渲染器同样被否决——渲染器的职责是净化与渲染，而机器选择的决策已经位于 `ui-conversation` 的 `MarkdownExternalLinks.open` 背后，设置、组合进来的面板与页面源站这些目的地知识本就在那里。

## 后果

与宿主机同局域网的读者只是在名义上失去公网链接的面板投递：这类链接现在开在自己的浏览器里，到达的是同一个互联网。把面板当作公网目的地通用代理的部署不再隐式获得该能力；这样的读者仍可打开面板手动粘贴任意 URL，面板自身的地址栏不受本次改动约束。同源站条款意味着以公网主机名访问的 harness 会把同主机链接交给面板——这是正确的（它们就是宿主本地服务），但在一个域名前挂多个公网应用时值得知晓。
