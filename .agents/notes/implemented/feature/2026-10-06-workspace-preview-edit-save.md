# Agent Note: Workbench preview edit + save (Plan B plugin pair)

Status: implemented

English | [中文](2026-10-06-workspace-preview-edit-save.zh.md)

## Problem

The workbench preview was read-only at every layer by design: `workspace.files.*` is `harniverse.observe` + read, the Host opens files `O_RDONLY|O_NOFOLLOW`, the read returns a 1 MiB prefix with no version, and the UI exposes no mutation action. Reading then writing back through that surface would truncate large files, drop byte order marks, normalize line endings, and overwrite concurrent edits with no conflict detection (the investigation `docs/investigations/02-preview-edit-save.md` in the parent workspace records the reference projects' failure modes). The Agent side already had the right write primitive — `ctx.fs.writeText` with `replaceIfVersion` (per-target lock, private staging, atomic publication, mode/DACL preservation) — but no user-facing route to it.

## Alternatives considered

- **Extend apiproxy and ui-workspace in place (Plan A).** Rejected: editing could not be removed per composition, CodeMirror would enter the `startup: critical` path, and the package's read-only identity, invariant, and README contracts would all flip while business contracts kept accumulating in the legacy proxy against the Typert direction.
- **Write through a session's execution world (Plan C).** Rejected as the main path: the workbench is Workspace-scoped (multi-session, usable with none running), so "which session's observation table" has no natural answer, and Agent permission presets would constrain a user action whose approver is the same user.
- **Reuse the reference projects' private HTTP routes.** Rejected: the web server carries no authentication; business mutations must ride the authenticated `/api` carrier with a declared capability.

## Decision

- **A plugin pair, per the investigation's Plan B and D-choice defaults.** Host: `@deepseek-ai/dsh-workspace-file-write` (`ctx.workspaceFileWrite`, Typert `@Remote`, `harniverse.operate`, Workspace-id scoped) with `open`/`stat`/`save`. Client: `@deepseek-ai/dsh-client-ui-workspace-editor` (CodeMirror 6, exact pins) registered into two new ui-workspace holes — `workbench.preview.document` (drawer placement) and `shell.overlay.preview.document` (overlay placement), same owner contract, one occupant. Without the editor row the preview is byte-identical to before and shows no mode toggle; with it, editable families keep their rendered preview and reach the editor through the Preview / Edit mode below.
- **Open is complete-or-refuse** (D1c, D10, D13): full read ≤ 1 MiB, decoded through the shared codec walk, `FsVersion` plus `{encoding, encodingSource, bom, eol}` returned; mixed EOL (`mixed-eol`), undecodable (`not-text`), oversize, symlink, `.git` segment, and escapes all refuse typed. Content arrives LF-normalized.
- **Save rides the Agent's primitive, not a copy of it** (D2b, D5a): `ctx.fs.writeText(replaceIfVersion)` under an explicit `workspace-write` policy rooted at the canonical Workspace directory, so the write shares fs-local's per-target lock with the Agent tools and inherits atomic publication and mode preservation. The encoding, BOM, and line-ending style are re-derived from the disk file inside the CAS window — the delivered sticky-decision write-back makes the Host authoritative, so the wire carries only `{content, baseVersion, saveId}` (a deviation from the investigation's `eol`/`bom` wire fields, closing the buggy-client corruption hole). Unmappable characters refuse with line/column (`FS_UNMAPPABLE` surfaces); a stale version refuses with `stale-version` plus the current version; `saveId` supplies the idempotency the Typert path lacks.
- **No Agent observation is recorded**, so an Agent's next guarded write reports `FS_STALE_VERSION`; after the commit point the service emits `workspace-file/saved` and injects one non-waking, path-only notice (D6b's semantics) into each live session whose canonical cwd is the Workspace path — 32-session cap, 10-second per session+path spacing.
- **Drafts live in the editor plugin's own store** keyed machine/workspace/path, carrying `{draft, baseVersion, eol, encoding, bom, status, conflict?}` and the serialized `EditorState.toJSON({history})`; the store is created once in `apply` and survives both placement switches (serialize-on-unmount, restore-on-mount) and machine re-registrations (entries stay addressed under their machine). Saves never enter ui-workspace's request fence, so a Workspace switch cannot abort one; the `beforeunload` guard covers page departure (D8a — no browser persistence for file content, ever).
- **Conflicts per D5a**: version CAS plus the conflict bar (compare via a unified diff over the shipped `DiffBlock`, discard-and-reload, confirm-overwrite). External changes are detected through a file-level `watchFiles` subscription and settled by comparing `stat`'s `FsVersion` only — the watch frame's version format is never compared with base versions (P1); the editor's own save echoes are suppressed by version equality.
- **Escape and focus per P3**: the preview's window-capture close defers while focus is inside `[data-workspace-editor]`; the editor's keymap handles Escape after the search panel's own binding and otherwise requests the owner's close; the preview's focus selector gained `[contenteditable="true"]`; the owner confirms before closing or dismissing a document reported dirty through `onDirtyChange`.
- **CodeMirror pins are exact** (D9, D13): `state 6.7.6`, `view 6.43.13`, `commands 6.11.1`, `language 6.12.4`, `search 6.7.2` plus the minimal language set; they inline into the editor plugin's own client bundle (the client bundle emits one `client.js` per plugin with no dynamic-chunk mechanism, so per-plugin composition is the lazy-loading boundary). `@codemirror/merge` stays out (D7a).

## Preview/Edit mode

An occupied hole adds a **Preview / Edit** toggle to the preview header for an editable family that is read complete and not truncated, so Markdown, sandboxed HTML, highlighted code, text, and CSV/TSV tables stay viewable while the editor row is composed. Nothing changes without a seat.

- **Preview is the default and is the pre-editor rendering.** The occupant mounts only in Edit. The mode is the per-tab `previewMode` map in the shared workbench store, read and written by both the drawer and the overlay entries, so it survives tab and placement switches and is removed by `closeTab` and the `ensureWorkspace` pruning.
- **Explicit encodings stay in Preview.** A re-open with an explicit encoding cannot be reproduced by the editor; Edit is disabled with `workbench.editorUnavailableExplicit` as its title, the preview shows the content decoded with that encoding, and the owner does not send `readOnlyFallback` (the member stays on the occupant contract). A Host-refused editor (mixed EOL, not text, over 1 MiB) leaves Preview one click away.
- **Unsaved edits outlive the editor's mount.** The dirty fact is also store state (`documentDirty`, keyed by tab id, dropped with the tab), so both placements agree and the close/dismiss confirmation holds in Preview mode. The occupant does not retract it on unmount while the draft account holds a dirty, saving, or conflicting entry; it reports `false` when the entry settles clean, and a save that lands after the unmount retracts the fact itself. Preview shows `workbench.previewStale` while the document is dirty. Closing a dirty tab after confirmation leaves the draft in the editor account; reopening and choosing Edit restores it.
- **Preview shows the saved text.** The owner contract has the optional `onSaved()`; the controller's `save` and `confirmOverwrite` resolve whether the text landed, and the occupant calls `onSaved` after a landed save or conflict overwrite. Each placement answers with a silent re-read of the tab's file (no loading state, body untouched) that updates `content` and the decode facts; a failed re-read keeps the previous text and logs a warning. CAS and encoding behavior are unaffected.

This note partially supersedes the "workbench remains read-only" clause of [the workbench note](2026-08-28-workspace-workbench.md): the workbench's *inspection* RPCs and stores stay read-only, while an editing occupant may be composed into the preview's document holes. That note remains active for the containment and slot-discipline decisions.

## Consequences

- A principal holding only `harniverse.observe` still cannot edit (the Remote requires `operate`, the same capability `terminal.write` requires); an observe-only Grant keeps the read-only preview.
- The process-local lock serializes user saves with Agent tool writes in one Host process; other processes keep the same probe→rename residual window the Agent tools have.
- The notice text is model-visible and therefore logged through the inbox; its verbatim text is pinned by the loader-composition test and the package README.
- `dsh-workspace/src/types.ts` now imports `SessionId` from `@deepseek-ai/dsh-session/types` (not the root) and `tsconfig.base.json` gained `@deepseek-ai/dsh-workspace` + `/types` paths entries, so the generated Remote projection's type-only subpath stays free of Host `Context` merges in Client programs.
