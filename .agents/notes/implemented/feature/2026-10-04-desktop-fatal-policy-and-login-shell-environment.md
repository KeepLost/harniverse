# Agent Note: Desktop fatal policy and login-shell environment — crash reports, first-fatal dialog, inherited Host environment, packaged DevTools

Status: implemented

English | [中文](2026-10-04-desktop-fatal-policy-and-login-shell-environment.zh.md)

Scope: `apps/desktop` (`src/login-shell-environment.ts`, `src/duration-env.ts`, `src/node-environment.ts`, `src/crash-report.ts`, `src/fatal-recovery.ts`, `src/entry.ts`, `src/main.ts`, `src/owned-host.ts`, `src/locale.ts`)

## Problem

Official sync 639ed01539 rows R17/R18/R25/R26: upstream hardens its desktop product with a login-shell environment import for GUI launches, crash-report files with a native fatal-recovery dialog, and packaged DevTools for the main window. Harniverse's desktop owns a different shell lifecycle — one window, tray-owned background lifetime, entry-owned exits, no plugin manager — so each capability had to land on our contracts rather than as a copy.

## Decision

- **One login-shell read at launch** (`login-shell-environment.ts`). POSIX GUI launches inherit only the session manager's environment, so `entry.ts` starts exactly one read at launch and hands its promise to the shell; `will-quit` aborts it (a second-instance launch that fails the instance lock therefore aborts its own probe through the same hook before exiting). Candidates are the account record's login shell (not `$SHELL`), then `/bin/zsh`, `/bin/bash`, `/bin/sh`; each runs as an interactive login shell (`-ilc`) whose rc files print a NUL-delimited `env` dump between two markers, with stdin closed (prompts read EOF) and probe guards (`DISABLE_AUTO_UPDATE`, `ZSH_TMUX_AUTOSTARTED`, `ZSH_TMUX_AUTOSTART`) that keep oh-my-zsh update prompts and tmux autostart from blocking a non-terminal read. The read completes at the closing marker — rc-started background children can hold stdout open after the shell exits. Shell values win over the inherited environment except the probe session's own keys (`PWD`, `OLDPWD`, `SHLVL`, `_`, the guards) and launcher-owned `DSH_*`/`ELECTRON_*` names: Desktop resolves paths such as `DSH_HOME` before the read, so the Host keeps the inherited values. The promise never rejects — every failing candidate is logged and the inherited environment returned. Each candidate is bounded by `DSH_DESKTOP_LOGIN_SHELL_TIMEOUT_MS` (default 10000 ms; the shared `duration-env.ts` reader accepts integers 1000–2147483647); timeout or abort kills the probe's detached process group. `win32` returns the inherited environment unchanged — GUI launches there already inherit the registry environment.
- **The owned Host inherits the user's real environment.** `connectNow` awaits the shared read before creating the Host, and `owned-host.ts` spawns it with the merged environment plus `ELECTRON_RUN_AS_NODE=1` (`node-environment.ts`). The old uppercase-allowlist `launchEnvironment` is deleted: a user's `HTTP_PROXY`/`HTTPS_PROXY` and `SSH_AUTH_SOCK` now reach the Host and its full-access shells — the Host already executes as the user, so hiding the user's own login variables bought no isolation.
- **Crash reports before the dialog** (`crash-report.ts`). One owner-only local file per fatal failure, in the Electron logs directory; `launchDesktopShell` sets the platform-conventional path via `app.setAppLogsPath()` before ready so the first report already resolves under it, and `start()` prunes old reports. Files are `0o600` inside a `0o700` directory, named `crash-<sortable time>-<source>.log`, newest 10 retained; pruning touches only names matching that exact syntax. Content: a header of facts (time, source, phase `startup`/`running` by Host readiness, app/platform/Electron/Node/locale, shell pid), the inspected error with its enumerable properties and cause chain (bounded sections), and the renderer's error-level console tail (64 KiB, whole oldest lines dropped first, one oversized line kept whole). A write failure logs and degrades to a dialog without a path — a diagnostic aid never blocks recovery.
- **First-fatal native recovery** (`fatal-recovery.ts`). The crash report is awaited first (bounded by 1 s) so the dialog can name the file; the dialog offers Exit/Restart (restart default), shows the error's tail with a truncation notice, and loops when a recovery operation itself fails. `EADDRINUSE` gets dedicated copy (quit the other process, then restart). Reports are deduplicated: the first fatal owns the dialog and later reports resolve immediately; during recovery-driven shutdown no dialog opens but the report still persists.
- **Fatal surfaces and deliberate deviations from upstream.** Sources are `host` (owned-Host start failure or death, including exit without shutdown acknowledgement), `renderer` (main-frame `did-fail-load`, ignoring the aborted `-3` navigation of a superseded load, and `render-process-gone`), and `main` (shell startup failure — report only: `launchDesktopShell` writes the report and rethrows, and `entry.ts` exits 1; a dialog cannot own an outcome before the window and tray exist, so upstream's launch-failure dialog is superseded by the entry exit with the report persisted). Upstream additionally has a `web-boot` fatal source and a disable-plugins dialog button; both are omitted deliberately — this desktop owns no plugin manager and plugin state is Host-side, so there is no web-boot boundary and a button with no owner would be dead UI.
- **Packaged DevTools for the main window.** `devTools: true` on the `BrowserWindow` plus two hidden `toggleDevTools` menu roles (one keeps the role's platform accelerator, one pins F12): the packaged renderer stays inspectable without a visible entry, and the tray menu carries neither. `win32` replaces the visible application menu with the hidden roles only — the tray already owns the shell surface there; other platforms keep the visible Harniverse menu with the roles appended.
- `locale.ts` gains the fatal-dialog copy (fatal summary, startup-failed title, EADDRINUSE advice, truncation notice, report path, reinstall advice, recovery-operation retry, Exit/Restart) and drops the now-dead `recoveryUnavailable`/`windowRecoveryUnavailable`/`stateWindowStopped` keys.

## Alternatives considered

**Importing the login environment per Host spawn.** Rejected: rc files have side effects (update checks, session banners); one read per application run gives every spawn the same view and pays those effects once.

**Keeping an uppercase-allowlist launch environment.** Rejected: the allowlist silently dropped the user's proxy and agent variables — the exact variables a desktop-launched full-access shell exists to inherit.

**A `web-boot` fatal source and a disable-plugins button copied from upstream.** Rejected: this desktop owns no plugin manager; there is no web-boot process boundary and nothing for the button to disable.

**A fatal dialog on shell-launch failure.** Superseded by entry `exit(1)` with the report persisted: before the window and tray exist there is no surface that can host the dialog loop, and the entry's exit is already the outcome.

## Consequences

Desktop-launched Hosts now see the user's real login environment (proxies, agent sockets, language settings) instead of the session manager's stub, and every fatal failure leaves a complete, owner-only diagnostic before any user interaction. The costs: one bounded probe subprocess per launch, and the full user environment reaching the Host — the same trust as the user running the Host themselves, which the owned-Host model already assumes. Hidden DevTools roles keep packaged diagnostics reachable without advertising a developer surface.

## Verification

- `apps/desktop/tests/login-shell-environment.spec.ts`: config default and override, candidate order (unreadable account record → fixed shells), delimiter parsing, merge rules (probe-session and launcher-owned names excluded), win32 passthrough, POSIX probes merging rc exports while ignoring other output, per-candidate failure recording with the next tried, completion at the closing delimiter while an rc-started child holds stdout, timeout ending a shell with its background children, abort ending the running shell group and skipping the rest.
- `apps/desktop/tests/duration-env.spec.ts`: millisecond env bounds; `node-environment.spec.ts`: Node mode over the provided environment and hostile `ELECTRON_RUN_AS_NODE` values.
- `apps/desktop/tests/crash-report.spec.ts`: sortable names, fact/error/console rendering with the absence notice, section bounds, `0o600` write refusing to overwrite an existing name, directory creation and write-failure degradation, retention pruning (matching names only) and its failure reports, bounded console tail that never splits a line.
- `apps/desktop/tests/fatal-recovery.spec.ts`: report persisted before the dialog and named in its detail, tail shortening with the truncation notice, whole short errors, surrogate-safe cuts, the EADDRINUSE copy with the report line intact, restart through stop with the dialog retried when stop fails, exit despite a stop failure, duplicate reports resolving immediately without another dialog, slow or failed report writes still opening the dialog.
- `apps/desktop/tests/main.spec.ts` / `owned-host.spec.ts`: renderer crash and owned-Host failure surfaced through the native dialog with a written report, startup-phase reporting for a Host that cannot start, awaiting the shared login-shell read before creating the owned Host, hidden DevTools menu roles kept out of the tray (win32 hidden-roles-only application menu), owned-Host spawn with the provided environment in Node mode.
- Packaged qualification on the three operating systems stays with the CI desktop jobs.
