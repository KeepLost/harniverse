# Agent Note：在失败的步骤关闭前记录未应答的工具结果

Status: implemented

[English](2026-09-19-failed-step-tool-results.md) | 中文

## 问题

一条已提交的 assistant 消息可能请求了若干工具，而调度器在所有结果落盘前失败。带着这些未应答的调用直接关闭步骤与轮次，会让后续模型请求对要求“工具调用与结果成对”的提供方失效。错误轮次已经关闭，崩溃尾部修复无法在恢复时补救。

## 决策

AgentLoop driver 在关闭失败步骤之前，为未应答的调用记录恢复结果，然后传播原始失败。实时步骤恢复与 `interruptedTurnClosers` 共享同一套增量 pending 调用跟踪与结果构造；实时 driver 仍拥有自己的步骤与轮次事件。步骤级观察者只保留已提交事件中的 pending 身份，不复制会话历史。调度器在拒绝前停止补充并排空已启动的分发，因此结果恢复不会与活跃分发竞争。

恢复保留已提交的结果，并按 assistant 的调用顺序输出。已记录 `tool/call` 但没有结果的调用获得 `TOOL_OUTCOME_UNKNOWN`，其文案警告不要盲目重试可能有副作用的操作。没有调用记录的 assistant 请求获得 `TOOL_NOT_STARTED`。调用记录先于准备阶段，不能证明工具体已运行，因此未知结果保持保守。

本决策只取代[并行工具调用执行](../feature/2026-07-10-parallel-tool-call-execution.md)中关于缺失结果的策略；其分类、并发上限、顺序与静默规则仍然适用。

移植自官方 DSH `6a6f350b94`（含 `8de4e51875` 的 pending 条目守卫），属 2026-10-02 wave-4 吸收；Harniverse v0 会话消息格式不变。

## 备选方案

**让调用保持未应答，以避免编造工具结果。** 未应答的调用使后续提供方请求失效。显式的未知结果错误记录了现有证据的边界，不声称成功、取消或无副作用。

**只在恢复或分叉时修复。** 普通失败路径已经记录 `step/end` 与 `turn/end`；开放尾部修复有意保留已关闭历史。恢复属于这些记录之前、driver 仍拥有失败步骤的窗口。

**只在工具调度器内修复。** 失败可能发生在 assistant 消息已记录、调度尚未开始之间。步骤 driver 覆盖该区间，并复用既有会话修复语义，而不是新增第二套调用/结果匹配实现。

**自动重试。** 分发即使结果缺失也可能有副作用。错误结果提供重试指引，轮次保留原始失败并等待后续工作。

## 后果

实时步骤失败后，后续请求、恢复与分叉都保有可用的调用/结果历史。恢复只追加结果；不移除 assistant 消息、不替换已完成结果、不执行工具、也不把失败轮次改成成功。日志使用既有事件类型与恢复码，格式不变。

已关闭的不一致历史轮次保持不变。实时恢复路径要求会话接受缺失结果记录；无法承诺在日志追加本身失败时完成恢复。
