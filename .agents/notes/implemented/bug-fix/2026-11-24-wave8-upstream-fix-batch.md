# Agent Note: Wave-8 upstream fix batch (Markdown parsing, clipboard, CJK emphasis, repeat reminders, refusals, file uploads, summary route, error taxonomy)

Status: implemented

English | [中文](2026-11-24-wave8-upstream-fix-batch.zh.md)

## Problem

Ten upstream fixes inside the frozen wave-8 increment (pin `4b399c39a6`, dsh 0.2.3-alpha.2) correct defects this tree shares. Each was verified missing here against the upstream diff before the port:

1. **Large Markdown freezes the main thread** — `mdast-util-from-markdown` 2.0.3 splices the event array per list item and `micromark-extension-gfm-table` 2.1.1 copies the event tail per cell; the streaming renderer re-parses the tail on every chunk, so a large table or long list stalls each frame (official `eafa4302a5`).
2. **Punctuation-led strong emphasis never opens after CJK text** — `针对**“…”**，` renders literal markers and the closer pairs with the next opener in the paragraph (official `f96500740f`).
3. **Copy buttons do nothing when the Clipboard API refuses** — a rejected `navigator.clipboard.writeText` returned `false` without trying `execCommand` (official `adc9d1bf64`, `81ee68dfba`, `54330f75e4`).
4. **`run_code` sub-calls pollute the repeat reminder** — nested executions share the agent's chain key, so a program issuing identical sub-calls trips a reminder on one `run_code` call and interleaved sub-calls reset a real loop (official `2c4f548d13`).
5. **A menu stays open beside another popup** — the shared context-menu button stops its pointer presses, so the menu's `pointerdown` dismissal never sees the activating click (official `85416f643a`).
6. **A provider refusal is reported as a malformed response** — `stop_reason: "refusal"` fell into the unsupported-stop-reason arm, losing the billed usage and the provider's explanation (official `e68c033493`, keeping the refusal path of `f250e23202`).
7. **Cancelling a turn as an image upload starts can end the Host process** — Node's `fetch` copies a `FormData` body from a detached task; aborting within the same turn fails that task with an unhandled `Invalid state: ReadableStream is already closed` rejection, which the launcher's fatal handler turns into a process exit (official `c64f311035`).
8. **Compaction summarizes on the route that just rejected the history** — after a request overflows, the latest header names the rejecting route; the summary replays nearly the same prefix, that route rejects it too, and overflow recovery dead-ends (official `9ebb02afb7`).
9. **Failures the registry cannot route on** — shell and filesystem argument failures were plain `Error`s; a forced background call raised an approval prompt before failing; a lone `sandbox_permissions` was told to add a justification the composition cannot honor; cancellation thrown by a tool body or a `tools/execute` wrapper carried no `ABORTED` identity; blank `web_fetch` URLs, malformed skill names, answerer failures, and failed workflow runs had no code (official `efc62d7b06`, `fc6afa97fe`, `9b4b278b3e`, `4f62401683`, `fda29f726d`, `1784d23da9`).
10. **Transport failure text is unbounded** — `web_fetch` placed the whole system error into the model-visible message (official `38921fcac5`).

## Decision

Each fix is ported in the upstream shape; deviations are recorded where this tree's contracts differ.

- **Markdown parsers**: `mdast-util-from-markdown` is pinned at `^2.1.0` in `ui-primitives` and the root, and the lockfile resolves every reference to 2.1.0 with `micromark-extension-gfm-table` 2.1.2. The lockfile was edited to exactly those references: a `pnpm update --depth Infinity` re-resolved unrelated transitive dependencies (tslib, aws-sdk, vitest peers).
- **CJK strong emphasis**: `cjkFriendlyStrong` adds the symmetric `cjkStrongOpen` branch (two markers, CJK text before, punctuation after). Single-asterisk emphasis and non-CJK adjacency keep upstream parsing. The `markdown-cjk-strong-open` Web scenario pins the assembled rendering.
- **Clipboard**: `writeClipboard` falls through to `execCommand('copy')` when the async API is missing or refuses, keeps the fallback total (the textarea is always removed), and returns focus to the copy control. Callers must invoke it from a user gesture: the fallback relies on transient activation and replaces the page selection.
- **Repeat reminder**: calls with `exec.parent` neither count nor reset the chain; only model-direct calls, `run_code` included, do.
- **Menu**: an open `Menu` closes on the activating `click` of an `aria-haspopup` control outside it, caught in the capture phase so a trigger that isolates its presses still closes it; `isExternalTrigger` still exempts the triggers a popup manages itself.
- **Refusal**: a Messages stream that stops with `refusal` yields its final usage and then throws `CONTENT_REFUSED`, keeping the provider's explanation when it supplies a usable one. The code is outside the default retryable set. The chat-completions protocol keeps its existing stop-reason handling; upstream carries no refusal mapping for it.
- **File uploads**: `DeepSeekFilesClient.upload` encodes the three multipart fields itself and sends a `Uint8Array` with an explicit boundary; `request` merges the caller's headers with the attribution and authentication headers. The chat-completions variant keeps its leading `purpose=user_data` field.
- **Summary route**: the summarization call and its policy override use one conversation route: the model that produced the latest `assistant/message`, then the model-policy concrete target of the durable `model/target`, then the latest request header, then the agent options. An explicitly configured `summarizationProvider`/`summarizationModel` pair still takes precedence. The answered route is read with a reverse scan of the session log at summarization time. This narrows the precedence the [replay token-meter Agent Note](../architecture/2026-07-15-replay-token-meter-service.md) recorded: a selected target now applies once it has answered, or before the first answer.
- **Error taxonomy** (the wave-7 error-base line continued):
  - `bash`, `pwsh`, and the `write`/`edit`/`apply_patch` sandbox controller reject escalation fields the schema does not advertise — a lone `sandbox_permissions` or a non-empty `justification` without a sandboxing executor — with `ToolArgsError` before the pairing check, approval, and working-directory setup. The shell tools also reject an unadvertised `run_in_background: true` there, so a forced background call no longer prompts first, and report command, description, and `timeoutMs` violations as `ToolArgsError`. A missing job runtime is `ToolContextUnavailableError`. The wave-6 orphan-justification tolerance still holds wherever the escalation fields are advertised; see the [wave-6 fix batch](2026-11-07-wave6-upstream-fix-batch.md).
  - The registry keeps the message and adds `{ name: 'AbortError', code: ABORTED }` when, after cancellation, a started tool body throws the signal's reason or an `Error` named `AbortError` without `HarnessError` identity; a `tools/execute` wrapper that throws such a value is classified the same way, as `ABORTED_BEFORE_DISPATCH` when the body never started. A `HarnessError` and any other failure keep their identity. See the [cooperative tool cancellation Agent Note](../architecture/2026-07-19-cooperative-tool-cancellation.md).
  - `web_fetch` blank URLs, `web_search` query constraints, and malformed skill names throw `ToolArgsError` (`INVALID_ARGS`).
  - `ctx.userQuestions.ask` wraps the answerer: a value that is not a `HarnessError` becomes `UserQuestionError` `PROVIDER_ERROR` with the original message and cause; another `HarnessError` keeps its name and code; a failure after the caller aborted is `ASK_ABORTED`.
  - `WorkflowResult` and `workflow/end` carry `errorCode`, the code of the fatal `WorkflowError` that ended an `error` run; `WorkflowErrorCode` gains `RUN_FAILED` for an error run without one, and the `workflow` tool fails with the run's code (`AGENT_CAP`, `CANCELLED`, or `RUN_FAILED`). The worker-thread host drops a reported code outside the seam union rather than rejecting the result.

## Alternatives considered

- **Keep the selected-model precedence for summarization** — rejected: it is the reported defect. After a switch to a smaller-window model the selected target names the route that just rejected the history, so the summary fails on input capacity or overflows again.
- **Port upstream's `compactionAnsweredRoute` session projection** — rejected for this batch: this tree's `sessionProjections` registry publishes every key to the Client wire and offers no host-only registration, so a projection would add a wire contract to read one provider/model pair. The scan runs only when a summary is produced.
- **Reject the whole worker result on an unknown `errorCode`, as upstream does** — rejected: the host already admits the typed `Result` message for its other fields and has no fail-closed path for a malformed one; dropping the code yields a routable `RUN_FAILED`.
- **Leave shell argument failures as plain errors and type only the new checks** — rejected: upstream's rule is that hand-checked argument constraints throw `ToolArgsError`, and retry, UI, and analytics cannot route on text alone.
- **Add a refusal mapping for the chat-completions protocol** — not done: upstream removed that protocol before the refusal work, so there is no reference behavior to port; recorded as a gap.
- **Refresh the lockfile with `pnpm update`** — rejected: it moved unrelated transitive versions across the workspace.

## Consequences

- A 600×10 table parses in about 170 ms where it took about 1.8 s, and a 6,000-item list in about 570 ms where it took about 750 ms; streaming re-parses multiply the saving.
- Chinese replies bold punctuation-led spans without spaces around the markers; copy buttons work under denied Clipboard permissions; `run_code` programs no longer draw or launder repeat reminders; a refused answer is reported with its explanation instead of `MALFORMED_RESPONSE`; cancelling during an image upload no longer exits the Host.
- Model-visible text changes: shell, filesystem, `web_fetch`, `web_search`, and `skill` argument failures gain the `invalid arguments: ` prefix, and `tool/result.error.info` carries `ToolArgsError` / `INVALID_ARGS`; a cancelled tool body or wrapper reports `ABORTED`; a failed workflow run reports its fatal code. Committed keyless snapshots pin none of the old texts.
- Once a session holds an assistant message, `/compact`, pressure compaction, and overflow recovery summarize on the model that produced the latest one, even when that model can no longer serve requests, until a newly selected model has answered once; `summarizationProvider` and `summarizationModel` override this.
- The per-target compaction policy is selected by the same route that runs the summary, which removes the earlier mismatch between the summarization target and the policy lookup.
- A forced background call under `enableRunInBackground: false` now fails as an argument error without an approval prompt.
