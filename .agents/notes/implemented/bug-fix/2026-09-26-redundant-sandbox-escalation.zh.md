# Agent Note: 冗余沙箱升权字段按无操作处理

Status: implemented

[English](2026-09-26-redundant-sandbox-escalation.md) | 中文

## 问题

模型可能在普通工具调用中通过 `sandbox_permissions` 重复声明会话的有效模式，有时还会传入空的 `justification`。注册表全局的目标枚举无法排除某个会话已经生效的模式。配对验证或严格拓宽检查因此拒绝本来无需额外权限的命令。[沙箱决策](../feature/2026-07-06-sandbox.md)负责审批边界；仅靠提示词无法保证每条模型路由都生成有效参数。

## 决策

sandbox 包导出 `normalizeRedundantEscalation`。bash、pwsh、write、edit 先解析本次调用的有效策略；仅当请求模式与有效模式完全相同时，才从参数副本中移除两个升权字段。已记录的模型调用保持原样；执行使用常驻策略，绝不发起审批。没有已解析策略时不移除任何声明。真正更宽的请求仍要求配对的非空理由与用户审批；更窄的请求仍在执行前失败。`approveEscalation` 对真正的升权请求保持严格拓宽约定。

shell 工具引导模型省略不会改变调用结果的可选参数，普通调用省略两个升权字段。工具 schema 要求仅在被拒命令的重试中使用严格更宽的目标和非空理由。文件修改工具 schema 对其升权字段采用相同措辞。仅在挂载后端公开升权能力时才出现与之相关的引导。

## 曾考虑的替代方案

- **只靠提示词**：否决。即便引导正确，模型的工具调用参数仍可能带上默认值或空占位符。
- **所有不拓宽权限的目标都按无操作处理**：否决。更窄的请求表达了冲突的权限选择，必须失败关闭。只有精确相等才属于冗余。
- **在工具注册表或审批服务中归一化**：否决。二者都不拥有逐调用的有效沙箱策略；实施约束的消费方在分派升权请求前解析该策略。

## 后果

同模式调用按已经生效的策略只执行一次，没有审批事件，也不改变权限。其他格式错误或不受支持的升权请求仍然报错。已记录的工具调用可以包含冗余字段，而执行的命令使用归一化副本。单元测试覆盖各消费方、共享辅助函数以及真正更宽和更窄的请求；无密钥组合快照固定模型可见的提示词和 schema。
