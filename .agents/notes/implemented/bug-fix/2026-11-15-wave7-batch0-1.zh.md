# Agent Note:Wave-7 批次 0 与 1 —— CI 彩排闭合、原型键分类、死控件、teardown 验证

Status: implemented

[English](2026-11-15-wave7-batch0-1.md) | 中文

## Problem

Wave-7 决策日暴露的四个独立缺陷,外加一项验证义务:

- 仅在 master 触发的 Sandbox 工作流在 #311 把 #304 错误分类学推进 master 后失败:`packed-install.e2e.ts` 的 `WORKSPACE_CLOSURE` 没有打包 `packages/util/error`,消费者彩排在按未发布线解析 `dsh-llm` 新增的 `dsh-error` peer 时命中 npm `ERESOLVE`。
- `ui-workspace` `preview-kind.ts` 的 `LANGUAGE_BY_EXTENSION` 是按文件扩展名索引的对象字面量,名为 `x.constructor` / `__proto__` / `toString` 的文件会命中 `Object.prototype` 继承成员而非未命中;`=== undefined` 守卫失守,一个函数流入 `CodeBlock lang` → `highlightToHtml` → `lang.toLowerCase()`,预览渲染崩溃(官方 `7d2d22aaf9` 修复的是同款隐患)。
- 工作区浏览器的未分组桶头部渲染了一个对 `workspaceId === undefined` 空转的新建会话按钮——与官方 `1d4aaa8bf9` 移除的是同一个死控件。
- 目标条的动作顺序为 pause/resume、edit、clear,两个恒定动词随相位动词的出现与消失而挪位(blocked 两者皆不渲染)。
- Row 12(agent teardown 加固)需要 RED-first 审读:逐条对照官方硬化验证我们的循环,只吸收缺失项。

## Decision

执行 wave-7 批次 0 与 1(owner 指令 2026-11-15):CI 彩排闭合、wave-20 杂项批中适用于本树的部分(④ Map 查表、① 死按钮、② goal 排序;③ boot-spinner 以 N/A 关闭——本树无启动画面),以及 row-12 验证。每个修复跟随官方补丁;不向我们不持有的形态移植任何东西。

## Realization

- `WORKSPACE_CLOSURE` 加入 `packages/util/error`,注释沿用先例(peer 解析、未发布线 ERESOLVE)。本地经完整 pack → install → confine 彩排验证(3 个测试)。
- `LANGUAGE_BY_EXTENSION` 改为由 `Object.entries` 构建的 `ReadonlyMap`;`previewType` 改读 `.get(ext)`,天然错过继承键。一个 spec 点名四个原型键文件名并期望纯文本。
- `ProjectRowItem` 只为真实 Workspace 行(`workspaceId !== undefined`)渲染创建按钮;一个 spec 钉住未分组头部无此按钮。
- `GoalBar` 排序为 edit、clear、相位动词殿后,恒定动词的座位不再挪动;一个 spec 钉住顺序。官方加载期稳定性的那一半不适用:我们的按钮由 phase 驱动、激活期间即在渲染,无异步弹入。官方 10px→8px 间距收紧骑在其 Queue 行几何上,我们没有该形态;间距不变。
- Row-12 验证逐条进行:生命周期信号(工厂 `abort` + ownership teardown 监听)、teardown 唤醒覆盖(`cancel({kind:'disposed'})` 清除闩锁;never-latch 守卫是关闭准入背后的纵深防御)、迟醒防护(`beginDispose` 关闭准入;迟到的 send 抛 `agent "…" is closing`——由 `cancel.spec.ts` "does not latch a wake landing after disposal begins" 钉住)、取消隔离与静默 teardown(单一记忆化静默点、驱动边界收容、scope 失败聚合、最终 flush 收容)、关机期间输入拒绝收容(`assertAccepting` 稳定消息,spec 钉住)。117 个聚焦测试全绿。无缺失;不吸收。

## Consequences

- 本批推进后 master 的 Sandbox lane 恢复;该 lane 仍只在 master push 触发,PR 检查永远不会跑发布路径彩排(流程缺口已记录于 `UPSTREAM-ABSORPTION-REVIEW.md`;是否加入 PR 触发由 owner 裁决)。
- 打开扩展名与 `Object.prototype` 键冲突的文件现在分类为纯文本,不再崩溃预览。
- 未分组头部失去一个从未可用的控件;创建仍可用在每个真实 Workspace 头部与空白行上。
- 有据缓议:官方 closed-admission 的*分类化*(我们抛稳定消息 `Error`,官方为编码错误类)。我们的消息是被钉住的准入契约;把它转入 wave-7 错误词汇是一次审慎的词汇变更,不是缺陷修复。

## Alternatives considered

**用 `--legacy-peer-deps` 修彩排。** 掩盖彩排存在的意义所系的每一次未来 peer 漂移;closure 清单即契约。

**移植官方 boot-spinner 修复。** 本树无对应面(`apps/web` 无画面);以证据 N/A。

**吸收官方 goal-strip 的 e2e 轮询改动。** 它稳定的是其激活加载挂载,我们的 phase 驱动渲染没有该问题;顺序钉定才是可迁移的部分。

**现在就把 `assertAccepting` 转成编码 `HarnessError`。** 搭车范围:它改变跨缝隙的抛出类型契约,应当有自己的处置,而非搭验证批的便车。
