# Agent Note: 通过系统标准别名使用 macOS spill 根目录

Status: implemented

[English](2026-08-31-macos-spill-root-aliases.md) | 中文

## 问题

本地 spill 后端在创建或读取产物之前拒绝路径中的每个符号链接组件，防止配置的重定向逃出私有存储根目录。在 macOS 上，Node 与系统 API 可能把临时目录写成 `/var` 或 `/tmp`，而这两个名称都是指向 `/private` 的系统标准别名。若把这两个系统组件视为任意配置链接，就会在执行所有权、权限与包含关系检查之前拒绝本来有效的私有 spill 根目录。

## 决策

`dsh-spill-local` 仅在 macOS 上、仅对开头的 `/var` 或 `/tmp` 组件进行规范化，将其转换为 `/private/var` 或 `/private/tmp`，然后再逐组件执行 `lstat` 遍历。其他平台与其他路径写法继续使用原始绝对路径。任意中间符号链接或配置的符号链接仍会失败；根目录和会话目录仍必须归当前用户所有、使用私有权限、属于真实目录，并在最终 realpath 校验中保持包含关系。这是本地提供方内部的平台适配；不透明的 [`SpillStore` 约定](../architecture/2026-08-16-durable-tool-result-retention.md)不变。

## 考虑过的替代方案

**通过 `realpath` 解析每个配置根目录。** 不予采用，因为这会接受任意符号链接重定向，并移除保护产物写入与读取的逐组件不跟随属性。

**要求 macOS 部署显式配置 `/private/...`。** 不予采用，因为标准运行时路径可以合理地使用 `/var` 或 `/tmp` 写法；调用方不应为了安全使用本地提供方而执行平台专用改写。

## 后果

位于 macOS 标准临时目录写法下的私有产物根目录可以工作，而自定义符号链接根目录仍然无效。若某个非常规的 macOS 兼容环境为 `/var` 或 `/tmp` 赋予不同含义，系统会有意把它解释成对应的 `/private` 路径，而不是跟随该含义。Linux 与 Windows 行为不变。
