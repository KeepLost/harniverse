# Agent Note: 删除中央插件台账

Status: implemented

[English](2026-09-25-remove-central-plugin-ledger.md) | 中文

## Problem

中央插件台账混合记录最初的上游清单、当前能力约定、已交付组合、实现状态和提交追踪。包 README、子系统参考、源码配置、生成目录和决策记录已经分别负责这些事实。要求每次变更再追加一行，之后再用一次提交补填 SHA，会制造相互竞争的权威来源与维护工作，却不能证明文档或兼容性声明正确。

兼容性尾注约定的动机有价值：审查者需要显式兼容性声明，以及检查该声明的命令。但语法检查只能证明某行含有所需标签，既不能证明增量兼容，也不能取代对实际持久化约定的验证。

## Decision

仓库删除中央台账、其兼容性尾注验证器，以及强制追加行和后续追踪 SHA 的工作流，不设置替代清单、重定向文件或中央兼容性检查。[架构文档](../../../../docs/architecture.md)说明组合与扩展点；[包参考](../../../../packages/README.md)和[子系统参考](../../../../docs/subsystems/README.md)负责当前约定。所属 Agent Note 保留决策、替代方案、兼容性理由与所需验证；Git 与 PR（Pull Request）承载实现历史。

最初导入的标识统一由[许可证决策](../process/2026-09-19-relicense-bsd3-inherited-mit.md)负责归属说明。现有包与子系统文档保留运行时约定；重复清单、状态标注和历史实现行直接删除，不迁移到其他位置。

本决策部分替代[会话约定摘要决策](../process/2026-09-20-session-contract-digest-gate.md)：仅删除其台账尾注机制。基于源码提取的摘要、已提交基线、结构性与增量漂移分类，以及持久化目录检查均保留。会话 v0 永久仅允许增量扩展；SQLite schema 版本继续独立且单调递增。刷新基线前，必须先在所属 Agent Note 中记录显式兼容性理由与验证；结构性破坏变更仍被禁止。本次删除不改变 schema 或会话数据，也不刷新摘要基线。

## Alternatives considered

**保留更小的台账或将其改名。** 第二份清单仍会重复所属文档并引入逐变更记账；移动文件会保留维护问题。

**用另一个中央兼容性注册表替代行标签。** 新注册表会重复决策记录，仍无法确认语义兼容性。基于源码的检查与对所属决策的审查已经提供相关证据。

**随台账一起删除会话摘要。** 摘要独立于文字格式检测实际约定漂移，删除它会削弱持久化格式保证。

## Consequences

仓库不再用一个手工维护的列表记录全部下游变更。读者通过当前所属文档了解行为，通过 Git 或 PR 了解历史。新增能力与组合变更仍须在同一变更中更新所属文档；后续上游集成仍在所属 Agent Note 中保留准确的来源修订。新增中央清单必须有单独论证的消费方需求，且现有所属文档无法满足该需求。

会话摘要 note 保持活跃，因为其冻结规则、分类局限和被否决的运行时注册表仍指导后续修改。受影响的调度器、首次使用、许可证和覆盖率 notes 仍保留独立的归属、持久性、归属声明或测试政策理由；删除其中的台账引用不替代这些决策。没有 note 仅因删除台账而符合归档条件；冻结归档继续作为历史快照。

## Verification

聚焦的[摘要 spec](../../../../scripts/gen-session-contract-digest.spec.ts)保留源码与基线一致性、增量与结构性漂移分类断言；仅删除已移除的台账格式测试。`verify-session-contract-digest` 与 `verify-persistence-catalog` 检查实际源码约定。Markdown 链接、note 格式与分类、换行、双语配对和生成的翻译提示词快照检查更新后的文档。活跃文档与执行路径不得依赖已删除的台账或其验证器。
