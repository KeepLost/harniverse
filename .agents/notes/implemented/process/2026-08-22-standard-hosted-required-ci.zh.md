# Agent Note: 标准托管的必需 CI

Status: implemented

[English](2026-08-22-standard-hosted-required-ci.md) | 中文

## 问题

拉取请求必需作业曾依赖组织自有运行器标签和由仓库变量控制的故障切换路径。这种拓扑让可合并性取决于仓库外部基础设施，而热备与基准测试定义被禁用后仍留在活动工作流中。陈旧定义和手册继续描述已经不存在的恢复路径。

`CI` 工作流还会响应 `master` 推送，但只负责填充 Wine 软件包缓存。GitHub 因而显示一次成功的 `CI` 运行，尽管该提交并未执行拉取请求中的覆盖率、快照、Python 运行时和 Windows 清单。

## 决策

[CI](../../../../.github/workflows/ci.yml) 只由拉取请求触发。必需的 Node 24 作业、Node 兼容矩阵、Python 检查、Wine 承载的 Windows 门禁、独立原生 Windows 清单和 `all checks passed` 判定均使用 GitHub 标准托管运行器。工作流不保留自定义运行器标签、自托管选择器、故障切换仓库变量、禁用的热备作业或休眠的大规格运行器基准测试。新修订会取消被取代的拉取请求运行，因为旧运行的结果无法描述新的分支头。

原生 Windows 清单继续独立于 `all checks passed`：Wine 在 `ubuntu-latest` 上提供必需的 Windows 构建信号，`windows-native` 则报告完整且不掩盖失败的 `windows-latest` 结果。任何列入清单的必需依赖失败、被取消或被跳过时，聚合判定仍会失败。

[Wine apt cache](../../../../.github/workflows/wine-apt-cache.yml) 作为独立工作流拥有默认分支缓存填充任务。它的名称直接说明所执行的工作，更新的 `master` 推送会取消过时的填充运行。拉取请求恢复默认分支缓存，同时缓存维护运行不再伪装成 CI 判定。

本决策取代已归档的[大规格运行器](../../archived/process/2026-07-22-evidence-based-larger-hosted-runners.md)、[串行参考](../../archived/process/2026-07-21-serial-cross-platform-ci-reference.md)和[故障切换](../../archived/process/2026-07-26-ci-failover-runbook.md)记录中的自定义运行器池与默认分支参考拓扑。

## 曾考虑的替代方案

**把禁用的自定义运行器作业保留为工作流文档。** 否决，因为可执行配置不是历史档案。失效作业会逐渐偏离活动运行器策略、Action 版本、缓存和测试，却仍显得具有权威性。

**每次 `master` 推送都重新运行完整拉取请求清单。** 否决，因为合并提交已经包含经过审查的分支头，而完整平台检查成本很高。分支保护使用拉取请求证据；默认分支无需为了填充一个缓存再并发复制整套检查。

**删除 Wine 缓存填充任务。** 否决，因为每个新拉取请求都将重复下载同一套 apt 依赖闭包。独立工作流既保留可复用的默认分支缓存，也不再把缓存维护误标为仓库验证。

## 后果

必需 CI 不再依赖组织运行器预配或可变的故障切换变量。托管容量仍可能排队或失败，但所有活动运行器选择器都在工作流本身中清晰可见且可移植。

仓库放弃热备演练和工作流内的大规格运行器基准测试。历史测量和理由冻结保存在归档中；重新引入自定义容量时，必须作出新的流程决策、提供活动就绪信号并重新审查信任边界，而不能复活失效 YAML。
