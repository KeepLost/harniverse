# Agent Note: Absorb batch 1 — webserver gzip, session-surface guards, duplicate-install safety, path canon, model-facing fs

Status: implemented

English | [中文](2026-09-06-absorb-batch-1-webserver-session-util-fs.zh.md)

## Problem

Four Absorb-soon items from the official increment carried real defects or gaps in Harniverse. The web server served every response uncompressed, paying full payload cost for the Workbench bundle. Typert Remote markers lived in a module-level `WeakMap`, so two installed copies of the protocol package held independent marker tables and a decorator run through one copy was invisible to `remoteMethods()` in the other. The workspace registry canonicalized whatever `fs.realpath` returned — a relative path like `.` was silently adopted from the Host's cwd (creating a workspace over the repository root), a Windows drive-relative path from the current drive, and a drive root produced an empty default title. The client-side workspace path join always used `/`, mangling `C:\` + `src\a.ts` into a mixed-separator path. `read_image` rejected every extension-less path outright, and the unread-mutation diagnostics surfaced two different wordings for the same policy violation. Two further survey items turned out to be non-defects on inspection: the session-surface replacement-endpoint and compaction-span orderings were already guarded by Harniverse's `replacementRange`/`assertProvenance`/`validateShadowMetadata` boundaries, and absence-after-reread was already the fs stack's settled contract.

## Decision

Port the official fixes at contract level. The web server gained optional gzip: `compression: 'none'|'gzip'` (default none), `compressionLevel` 0–9 (default 1), `compressionThresholdBytes` (default 1024; unknown-length streams stay eligible), q-value negotiation between gzip and identity through `negotiator` with a `vary: Accept-Encoding` either way, and exclusions for already-encoded bodies, `no-transform`, 206 content-ranges, SSE, and no-socket synthetic responses; the shipped web composition enables gzip at level 1 over 1024 bytes exactly as upstream publishes it. Typert Remote markers moved from the module `WeakMap` onto a versioned, frozen, non-enumerable prototype descriptor (`@deepseek-ai/dsh-typert-protocol/remote-methods` v1) that any installed copy can read, with malformed descriptors rejected as `TypeError`; the downstream `requiredCapability` extension rides along unchanged. The workspace package now rejects any path that is not fully qualified (POSIX-absolute, or on win32 a real drive/UNC root — `C:` and `\work` stay relative) before `realpath` can adopt it, and derives the default title from the final path segment or, for a root, the root's own spelling; the client-side join picks the separator from the cwd's own style and only when the cwd actually contains backslashes. `read_image` sniffs PNG/JPEG/GIF/WebP signatures for extension-less paths, defers the deployment media-type check until after the bytes are read, and reports decode failures with dedicated messages; unread-mutation diagnostics were unified to the official single wording with the original error chained as cause. For the two non-defects, the official regression scenarios were ported as tests to pin the existing guards, not as code changes.

## Alternatives considered

**Follow upstream's new `dsh-util-values` package for the shared primitives.** Rejected: every Harniverse counterpart of those primitives is already a pure function with no module-level mutable state, so repackaging would be churn without a safety gain; only the protocol-descriptor fix carries real cross-copy risk and it landed in the protocol package itself.

**Compress in each route or in the fallback seat instead of one middleware.** Rejected: per-route opt-in would miss routes added later and cannot apply the negotiator's identity-vs-gzip decision uniformly; the single socket-backed middleware boundary is the official seam and leaves route and error handling untouched.

**Adopt relative workspace paths by resolving against an explicit base.** Rejected with upstream: adoption from any base silently relocates a workspace when the process starts elsewhere; rejecting non-qualified paths at the `realpath` boundary keeps the uniqueness canon total.

## Consequences

Deployments can halve their wire cost by enabling gzip; duplicated protocol installs interoperate; workspace creation can no longer capture Host-cwd or drive-relative directories; drive roots get real titles; mixed-separator Windows joins stop reaching the client; models can read extension-less images and see one stable diagnostic per policy violation. Backward compatibility: gzip is opt-in per composition (shipped web bundle opts in), so existing listeners stay identity-encoded; the stricter workspace rejection only affects paths that previously produced wrong workspaces. Evidence: RED-first regressions for the gzip composition, prototype descriptors, path qualification (including the reproduced `create('.')` cwd-adoption), separator joins, diagnostics normalization, and sniffing all fail on pre-fix code and pass after; the two non-defects are pinned by tests that pass against current code unchanged. Focused suites: webserver 8, compaction+session 543, and the typert/workspace/client/fs closure of 2037+352 tests green; `doc-sync` 29/29, `typecheck`, `oxlint`, and `knip` clean; per-file coverage at 100% on every touched source file.
