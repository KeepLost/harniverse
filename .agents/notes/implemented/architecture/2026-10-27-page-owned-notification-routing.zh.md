# Agent Note: 按页面归属的浏览器通知路由

Status: implemented

[English](2026-10-27-page-owned-notification-routing.md) | 中文

## 问题

连接同一个 Harniverse 实例的每个浏览器页面都各自打开全会话的 `events.mux` 订阅，并独立评估每个会话事件以决定是否提醒，只有两道闸门：同浏览器内的 `BroadcastChannel` 仲裁（每个浏览器选一个呈现标签页）与各页面自己的设置开关。当多个浏览器——或同一浏览器在多台机器上——指向同一实例时，每个页面对每个会话的出现都会响铃：通知越过了任何客户端机制都无法仲裁的页面与机器边界，因为不同浏览器的页面之间不存在共享通道。

## 决策

通知的检测与仲裁移到主机；页面声明在场。所有者的规则：**当前打开某会话的页面接收该会话的通知；没有任何页面打开的会话不投递**（明确的所有者决策——没有页面打开的后台会话保持静默）。

- **在场绑定。** `ConnectionController` 为每次页面加载铸造一个稳定的 `page` 令牌，并随每次 mux 打开携带（URL 查询参数 `page`，在 WebSocket 与 SSE 两种载体上都与既有 `since` 游标规则一同校验）。主机把令牌绑定到该页面的每条存活 mux 流；绑定随流消亡，重连则以同一令牌重新绑定，因此在场状态无需心跳即可跨越重连。
- **认领。** 单次调用 `events.adopt({page, sessionIds})` 是幂等的整体替换，由 sessions 运行时在本页当前会话变化时发起（尽力而为：丢失一次调用只意味着静默到下一次变化）。每个会话按声明顺序排列，最近声明者拥有投递权；拥有者最后一条存活流关闭时回落到前一个声明者。
- **中央检测。** API 代理中的一个 `NotifyDetector` 折叠消费 live 源——持久化的 `turn/end` 原因、被请求的审批与提问（resolved 前每个 rpcId 只响一次，因此按流的 mux 回放永不响铃）、后台任务终态边沿、`goal` 投影进入 blocked、以及 live 的 agent 错误——并把每次出现交给投递汇。检测契约与退役的客户端检测器逐条一致（aborted／max-tokens 回合与 killed 任务保持静默）。
- **投递。** 投递汇只把一个 `session/notify` 帧（种类、去重 `sourceKey`、以及供本地计划评审分类的提问载荷）推到拥有者页面存活的 mux 流上，且每条流照常通过自己的会话可见性栅栏（子代理会话只到达被授权寻址的流）。没有拥有者或没有存活拥有者流：丢弃。
- **客户端消费。** `ui-sound` 保留其补充 mux 订阅，但只折叠 `session/notify` 帧；通道分类（子代理来源）与提问分类仍通过会话列表在本地完成。host 流循环与 `BroadcastChannel` 跨标签机制被删除——单拥有者投递同时取代了两者。

认领除帧路由外不授予任何能力（`harniverse.observe`，读效果）：页面只能收到自己的流本就能看到的会话的出现。

## 后果

- 没有任何页面认领、却仍在服务的会话按设计保持静默：后台会话在任何页面打开它之前无处响铃（业主接受的取舍；原始事件流照常下发，未来的环境音界面无需改协议即可认领）。
- `events.adopt` 加入必需客户端面（`harniverse.observe`、效果 `read`）：connection/runtime 的测试替身各补了一个桩——每个新的一元域都要付的同样成本。
- 检测权威完全移到服务端；过期的客户端既无法退出、也无法为其页面从未打开的会话响铃，且 ui-sound 的消费者与 `session/notify` 协议耦合，而非原始事件词汇。
- 从不发送 `page` 令牌的端（非浏览器 Remote、脚本）保持今日行为：它们完全收不到 notify 帧。
- 认领跨重连存活（令牌在每次 mux 重开时重新绑定），但不跨整页刷新；新令牌在运行时于下一次 current 变化重新声明之前没有任何认领。

## 验证

`notify-detector.spec.ts` 逐条钉住折叠规则；`api-proxy-notify.spec.ts` 通过真实代理钉住仅拥有者投递、最近声明者仲裁、流关闭回落、无认领丢弃（原始事件照常流动）与整体替换；WebSocket 与 SSE 载体测试在两种载体上钉住 `page` 查询参数；运行时测试钉住当前会话变化时的认领与无令牌时的静默；重写后的 `ui-sound` 套件以逐文件全覆盖钉住 notify 帧消费者。

## 考虑过的备选方案

**保留客户端检测，另加跨浏览器仲裁。** 不同浏览器的页面之间不存在不经主机路由的共享通道；只搬移仲裁意味着每个页面仍要评估每个事件，而主机只回答「谁可以响」——比在事件源头检测一次的机制更重。

**向每个页面投递，由客户端按认领过滤。** 每个页面都会持续接收（并分类）它从未打开的会话的出现，且被攻破或过期的客户端无法在服务端被静音；在投递点路由才从构造上落实所有者的规则。
