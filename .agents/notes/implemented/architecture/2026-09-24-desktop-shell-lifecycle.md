# Agent Note: Desktop shell ownership and authenticated browser lifecycle

Status: implemented

English | [中文](2026-09-24-desktop-shell-lifecycle.zh.md)

## Problem

A desktop window adds native process and filesystem authority to the Web application. A loopback connection can also be an SSH tunnel, so its address cannot establish local ownership. Closing a window can interrupt active sessions if presentation and Host lifetime share an implicit teardown path.

## Decision

The [Electron shell](../../../../apps/desktop/src/main.ts) owns one window and one active connection. A local connection owns only the child returned by its distribution-controlled Host factory. An `existingHost` connection accepts HTTPS or loopback HTTP and keeps process, credentials and workspace paths on the connected Host. Renderer requests cannot choose an executable, configuration file or package-manager command.

The window loads the shared Web entry. Its sandboxed [preload](../../../../apps/desktop/src/preload-web.ts) creates or reuses a persisted non-exportable P-256 browser key and sends only its public key through the owned child's private enrollment channel. The Host records the exact key, enrollment and Grant association; later boots restore that association and recheck the live Grant. Revocation, expiry or unavailable authentication cannot recreate authority. The shared [browser authentication lifecycle](2026-09-08-browser-authentication-lifecycle.md) owns signed session exchange, renewal, revocation and recovery. The owned Host uses a stable loopback origin and a persistent browser partition separate from each external origin. A consumed bootstrap cannot approve another key; existing Hosts use ordinary browser enrollment. The bootstrap supplies neither a permanent bypass nor a bearer credential through the renderer bridge.

The context bridge exposes fixed operations and contains no raw IPC object. Main-process admission checks the owned WebContents, exact main-frame identity and current document authority. The launcher requires its exact file URL; the connected app requires its HTTP origin and a matching non-inherited document URL. Cross-origin navigation, popups, webviews, permission requests and automatic downloads are denied.

The existing [directory-picker capability](2026-07-28-directory-picker-capability-seam.md) keeps workspace adoption in the shared client. The local Host's Provider requests the owned shell dialog and receives a typed selection or cancellation. Renderer selection accepts no path argument, and an external connection cannot use the shell's local chooser. A selection that outlives its owning connection is discarded.

A retained tray or menu-bar icon gives the hidden window a visible return path. The application does not register OS login startup; after login the user launches it and selects the local Host. Schedules run only while that Host is running. Window close hides it while work continues. Logout, reboot and explicit Quit stop the owned Host. Explicit disconnect or Quit observes Host activity and warns with a retry path when work is active or observation is unavailable; cancellation leaves the Host attached. Once the owned Host is known to be stopped, the shell can release the connection even if its exit was unclean. Updates retain the stricter requirement for acknowledged zero-status exit. An external Host continues running after the shell exits.

Renderer crashes return to the connection page without terminating the Host. Child failure returns a credential-free recovery message and retains process ownership until teardown settles. Serialized connection transitions prevent a second owned child from overlapping the first, and the application instance lock routes later launches to the same window. Product identity is `dsh-harniverse` with application id `com.keeplost.harniverse`.

The [Desktop Host](../../../../apps/desktop-host/README.md) composes the distribution's authenticated Web bundles in a dedicated home and disposable Loader root. App-local Providers implement HTTP admission and native directory picking; the control Consumer observes existing authentication, session, terminal and scheduler services. Executable dependencies belong to the application closure and cannot be changed by user profile patches or runtime package installation. Desktop does not silently adopt the CLI home, credentials or package-manager state. Electron's embedded Node runs the owned Host and the W09 [PTC Provider bootstrap](2026-09-23-ptc-runtime-naming-and-bootstrap.md). The production assembler carries the complete pinned Playwright 1.61.1 Chromium payload: Chromium revision 1228 / Chrome for Testing 149.0.7827.55. `runtime-input.json` and `offline-assets.json` require the browser executable, version, revision and Playwright version; the packaged Profile validates the anchored path before boot and sets the existing browser-controller Provider's `executablePath` with `sandbox: 'auto'`. Current source branding uses one Harniverse blue-H mark for the native window, tray and generated PNG, ICO and ICNS icons, with the Electron default icon fixed to that asset family.

The shell, Host runtime and package manager form one update unit. The native **Install update…** menu selects a local artifact with an adjacent `.manifest.json`; identity, newer version, OS/CPU, filename and SHA-256 are validated before explicit consent. The digest proves byte integrity, not publisher identity. No remote update feed is configured. [Update transactions](../../../../apps/desktop/src/update.ts) inspect owned work, lock admission, inspect again, and require idle work plus acknowledged successful exit before installation. Active schedules must be paused or completed. External connections only detach; their Hosts are never stopped or updated.

The main process atomically persists the journal before effects. A writable running AppImage retains and verifies the previous executable before atomic replacement and relaunch; restoration only overwrites the candidate owned by that transaction. Other Linux launches retain the current installation and open the selected AppImage separately. Windows NSIS and macOS DMG hand off to native installation without automatic installer rollback. Startup recovery replays validated records, requires fresh consent after a pre-install interruption, and records completion when the expected application version starts. This is a version-start check, not a comprehensive runtime health check. Invalid recovery disables updates for the launch and preserves recovery files.

## Alternatives considered

macOS disposable Chromium profiles use `--use-mock-keychain`, matching Chromium's documented automation switch for avoiding blocking Keychain dialogs. The native failure reached a blank rendered frame but no navigation request; native qualification must confirm the effect of this correction. The loopback qualification page serves a deterministic high-entropy static text document so the rendered JPEG proof remains above its 10KB threshold across platform encoders without depending on inline script execution. Browser qualification snapshots hardlink immutable payload files where supported and copy the policy file to a private inode before changing it; Windows uses the native recursive copier so assembled pnpm junctions remain bootable. The sealed source inventory is rechecked afterward. Filesystem preparation has its own bounded 60-second lifetime, while Host/browser operations retain a 60-second lifetime on POSIX and a 120-second cold-start budget on Windows after physical staging, with 30-second IPC/RPC limits. This keeps staging cost separate from runtime progress and retains bounded Host stderr, fatal-message and exit diagnostics; stdout is captured where the platform stream is usable.

Browser qualification consumes frames concurrently with the navigation response and retains bounded, fixture-only Chromium stderr and exit observations. This preserves evidence of renderer progress while a command is pending; a rendered frame cannot waive the navigation acknowledgement. The local subprocess Provider uses the absolute `SystemRoot\System32\taskkill.exe` for both ordinary and inspected Windows process trees: an empty `PATH` otherwise prevents termination even after navigation and rendering succeed. Native regressions require both the root and its descendant to disappear, preserving the existing escalation and exit-wait contracts.

Browser artifact qualification navigates after the attachment snapshot grants control, even when the snapshot has no image yet. Waiting for a blank-page image before navigating can stall a valid attachment. The rendered proof still requires a substantial JPEG, the destination title and an observed local-origin request; bounded phase diagnostics distinguish attachment, navigation and teardown failures. Windows PTY qualification gives GUI Electron a console-owning `cmd.exe` parent and releases the ConPTY worker after natural exit, while retaining empty `PATH`, embedded-runtime output and successful-exit checks.

Built Host qualification uses `vitest.desktop.config.ts` after an explicit Host build in `test:desktop`. These `.e2e.ts` cases cannot join the source-only unit/coverage inventory: their subprocess entry and shared Web runtime are build artifacts. Authentication availability recovery does not invalidate an in-flight authorized activity sample; unavailability and revocation do, and the final Grant checks remain mandatory. Packaging resolves staging aliases before creating directories and rejects output inside the input runtime; POSIX executable-mode checks apply only on hosts that expose those bits.

The private Host uses Node's `import.meta.main` to recognize process entry. Comparing the module URL with the argument path misclassifies macOS `/var` aliases and directory junctions after the module loader resolves them. The built-process regression launches through a directory alias and still requires normal authenticated readiness and acknowledged exit; ownership tests compare canonical paths and shell tests derive native file URLs.

An independent desktop business UI duplicates plugin composition and authentication behavior. Loading the shared Web entry keeps these capabilities under their existing owners.

Address-based filesystem locality misclassifies loopback tunnels. Explicit child ownership provides the authority required for a local native picker and process shutdown.

Unconditional close-to-quit interrupts background work, while invisible background operation removes the user's return path. The retained tray and explicit activity-aware Quit preserve both work and control.

Mutating a shared CLI profile or installing executable plugins into Desktop would give multiple owners control over one application closure. A dedicated profile and whole-unit updates keep the runtime reproducible. Treating manifest checksums as publisher authentication or promising automatic native-installer rollback would exceed the mechanism's guarantees; local selection and explicit consent expose those limits.

## Consequences

The shell retains a small native trust boundary and depends on the Host's actual-exit and authenticated enrollment contracts. Its browser-device adapter shares the Web client's persistence format, so changes to that helper require verifying the desktop bootstrap together with the Web gate.

Focused [lifecycle](../../../../apps/desktop/tests/main.spec.ts), [IPC](../../../../apps/desktop/tests/ipc.spec.ts) and [preload](../../../../apps/desktop/tests/preload.spec.ts) tests replace Electron at its module boundary and exercise ownership, rejection, crash recovery and shutdown settlement without a model provider. The final branded Linux x64 AppImage and unpacked artifact qualified real Electron Host authentication and CDP browser behavior with inventory SHA-256 `0acb0a809a1433abc933c47862604401b2c911cb68548654fd4204c86db7518f`: a 12,079-byte JPEG frame with the expected title, one local request, zero pages after close and acknowledged exit status 0. The same qualification passed unauthenticated 401, signed exchange, plugin bootstrap, rendered UI, Session listing, device-key reuse after restart, close/hide with Host alive, reopen, two acknowledged Host closes and empty command-path execution. Native qualification passed Electron 43.4.0, embedded Node 24.18.1, Koffi, sharp, PTY, PTC, SQLite and pnpm 11.7.0 with no inventory errors or warnings. Installed Windows and macOS artifacts, their CI lanes, and release signing remain separate qualification gates.

The minimum release qualification matrix is Linux x64, Windows x64 and macOS arm64. Other declared CPU targets have no support claim until qualified. Branded Linux x64 browser-inclusive artifact qualification is complete locally; Windows/macOS artifact qualification and three-OS CI verification remain ongoing. The Electron UI does not itself supply the Session-bound Host-CDP browser; the packaged Chromium payload is a separate required runtime asset. Release signing/notarization, including Windows EV signing for a public installer, is a public-release gate and does not block source implementation or local artifact verification.
