# Agent Note: Host-side key picking and path-based key credentials on the remote-hosts surface

Status: implemented

English | [中文](2026-09-29-remote-host-key-file-picker.zh.md)

## Problem

The add-host form offered exactly one way to supply a private key: paste the PEM text into a textarea. Operators keep keys in files (`~/.ssh/id_ed25519` and company), so every save began with `cat` and a clipboard. The form also used a separate password and passphrase field where one shared secret input would do, and its visual language (sidebar trigger geometry, page skeleton, button and input styling) did not match the sibling center views, which made the whole surface read as bolted on.

A key file lives on the machine the Host runs on, so the path must be picked and read there. An interim cut read the file through the browser's own `<input type="file">` on non-`native` compositions — wrong machine: a remote or SSH-launched Host serves an operator whose browser machine is not the Host machine, and the uploaded content left the Host's boundary for no benefit. The shipped design keeps every step host-side.

## Decision

The directory-picker seam gains a single-file interaction instead of a second service. `DirectoryPickerNativeCapability` extends to `pickFile(signal, request?)` with `DirectoryPickerFileRequest { title?, defaultDirectory? }`; the `browse` arm is unchanged, and unknown-kind consumers keep hiding the affordance. The native backend implements it per platform: `choose file default location` through osascript on macOS, `--file-selection --filename=<dir>/` (Zenity) and `--getopenfilename <dir>` (KDialog) on Linux, and the Win32 `IFileOpenDialog` child gains a file mode plus best-effort `SHCreateItemFromParsingName` + `SetDefaultFolder` seeding (an unusable seed degrades to the dialog's own start location instead of failing the pick). A start directory the host cannot see is dropped at the adapter boundary — osascript would otherwise hard-fail the whole chooser. The Electron owned-Host path threads `pickFile` through the same parent-callback IPC as `pickDirectory` (`file-pick`/`file-result`/`file-cancel` messages with the same single-flight and abort rules).

`remoteHosts.keyFilePicker()` (`harniverse.observe`) is the routing probe: `{ kind: 'native' }` when the host can open its own chooser, `{ kind: 'browse' }` otherwise. `remoteHosts.pickKeyFile()` (`harniverse.administer`) is the `native` half: it resolves the picker through `ctx.get('directoryPicker')` (optional service — a composition without the `native` capability fails fast with `KEY_PICKER_UNAVAILABLE`), seeds the chooser at `join(homedir(), '.ssh')`, and returns `{ path }` — the picked file's host-local path, absent on cancel. The `browse` half is a named listing RPC in the same namespace: `remoteHosts.listKeyFiles(input)` (`harniverse.administer`) lists one host directory level at a time — directories first, then files, each name-sorted — starting at the operator's `~/.ssh` (falling back to the home directory) and bounded at 1000 entries with `truncated` set when the bound bites. Directories enter the next level; files pick directly, so the chosen credential is always a concrete file. A relative path rejects as `INVALID_INPUT`; an unreadable level reports `KEY_DIRECTORY_UNREADABLE`. The dialog lives in ui-remote-hosts itself, so no cross-package slot or directory-picker dependency couples the key flow.

Key credentials are host-local paths, never uploads. `AuthSecrets`' key arm carries exactly one of `privateKey` (inline content — pasted text) or `privateKeyPath` (an absolute POSIX or Windows path); the login form defaults to the path. With `storeCredentials` the record keeps `keyPath` — a plain string naming a file on the Host machine, in the company of `dshHome` and other host-local paths, never a secret — plus the encrypted passphrase reference; inline material keeps flowing into the credential provider as before. The Host itself reads the file whenever the credential is used — `verify` and `connect` — under a 64 KiB bound: an oversized file reports `KEY_FILE_TOO_LARGE`, a vanished or unreadable one `KEY_FILE_READ_FAILED`, and foreign chooser failures are contained as `KEY_PICKER_FAILED`. `RemoteHostsError` subclasses the typert `RemoteError` under the carrier's registered `remote-host-failed` code, carrying this package's own closed code in `details.reason`; the form maps the actionable reasons to localized copy. The carrier vocabulary is closed, so an unregistered code (the first cut's `KEY_FILE_READ_FAILED` and friends) made the client's response parse reject the whole failure and surface a schema dump instead of any diagnosis — the regression this reason channel replaces.

The browser surface is rebuilt to the schedules-view skeleton: fixed header with a connected-count summary and action row over a scrolling card list; the editor is a right-hand drawer (`role="dialog"`, Escape closes); tokens replace the ad-hoc palette; the phone form follows the frame's `data-viewport='phone'` convention instead of a media query. Key login shows an editable path input (the `native` chooser fills it; the `browse` dialog fills its directory part; `absent` or a failed probe leaves manual typing — the standing degradation rule for unknown interaction kinds) and a `paste key text instead` checkbox whose two states are mutually exclusive — pasting enabled disables the path input and pick button, unchecking re-enables both and hides the textarea. One shared password input carries the login password or the key passphrase for the selected method; a change to any tested field invalidates a completed connectivity test through the existing `testedFields` rule.

## Alternatives considered

- A browser `<input type="file">` like the attachment flow: rejected because it reads the browser's machine while the key lives on the Host's, displays no host path, cannot seed `~/.ssh`, and ships private key material across the wire for no benefit.
- A generic `host.pickFile` RPC returning arbitrary host file content: rejected as a wider security surface than the feature needs; `pickKeyFile` stays a named, capability-gated operation in the remote-hosts namespace that never proxies to a connected remote host, and it returns a path, not content.
- Extending `pickDirectory` with a mode flag: rejected because directory and file selection are different interactions of the same backend, which is exactly what the seam's discriminated capability union models; a boolean flag would make every caller branch.
- Keeping persisted host configuration free of paths (content references only): rejected for keys because the path is a fact about the Host machine, not a secret — storing it mirrors `dshHome` — while reading at use time turns a moved file into a closed, actionable `KEY_FILE_READ_FAILED` at `verify`/`connect` instead of a silently stale copy of the key. Inline pasted material keeps the one-shot `AuthSecrets` and credential-storage rules.
- Seeding the dialog from the client (passing `~/.ssh` from the browser): rejected because the Host owns the dialog and the home directory that matters is the Host account's; the seed is computed host-side.
- Reusing the browse directory-picker surface through a cross-package slot (the interim cut's `remoteHosts.keyDirectoryFlow` third hole): rejected because it coupled the picker package to ui-remote-hosts while serving a worse interaction — directories only, with the operator hand-completing the file name. A named listing RPC keeps the wire vocabulary closed, the dependency graph flat, and the pick on a concrete file; the picker package stays at its two-hole registration.

## Consequences

Key picking follows the composed interaction everywhere and always on the right machine: `native` where the operator sits at the Host's display, the in-app key-file browser for `browse` compositions (the normal case for remote, headless, or SSH-launched Hosts), manual path typing or pasting always available. The win32 COM additions (slot-11 `SetDefaultFolder`, shell32 parsing) are fake-tested through the existing bindings/worker harness; the real-COM path is exercised only on actual Windows hosts, matching the pre-existing picker's test posture.

Saved key logins now reference a host-local file; moving or deleting the file surfaces at the next `verify`/`connect` as `KEY_FILE_READ_FAILED`, and passphrase-only updates no longer rewrite stored key material. The IPC protocol between the Electron shell and the owned Host child grows `file-pick`/`file-result`/`file-cancel` with exact-key validation mirroring the directory messages.

Verification lives in the native-picker suite (per-platform file adapters, seeded and dropped start directories, AppleScript escaping, cancellation), the win32-dialog logic/bindings suites (file-mode options, `SetDefaultFolder` success/failure/degradation, worker mode and seeding), the desktop-host composition and lifecycle suites (callback threading, correlated `file-result`, abort), the remote-hosts coordinator suite (probe reporting for all three kinds, happy pick, cancel, unavailable picker, path-based verify/upsert/connect end to end with read failures), the secrets suite (path storage, use-time reads, size and read bounds), the typert roster, the keyfiles suite (default start, ordering, symlink classification, entry bound, unreadable levels), and the key-browser and browser view suites (probe-routed affordances, level navigation and concrete file picks, stale-settlement invalidation, manual-paste exclusivity, shared credential field mapping, `KEY_*` and connect-reason localization, Escape drawer).
