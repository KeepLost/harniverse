# Agent Note: 手机竖屏将侧边栏隐藏到浮动角落入口之后

Status: implemented

[English](2026-09-12-phone-portrait-floating-sidebar-entry.md) | 中文

## 问题

手机竖屏（框架宽度 < 600px）会让侧边栏收起后的 56px 图标栏作为网格轨道占据整条左边缘。在竖屏手机上这条轨道是最昂贵的界面元素：它吃掉 390px 视口约 14% 的宽度，只为显示一列图标，而真正的内容——对话——只能在剩余空间里挣扎。横屏（600–1023px，`compact`）预算不同，轨道在那里观感良好；用户要求竖屏做到「不召唤侧边栏时，它好像不存在」。

## 决策

- `phone` 形态下侧边栏**两种状态都不占网格轨道**。收起时侧边栏子树保持挂载（保 identity，遵守框架的永不卸载契约）但 `inert` 且 `aria-hidden`，并去掉列的轨道边框，避免画出 1px 接缝。展开时沿用现有 overlay 抽屉，按夹取宽度覆盖会话栏。会话栏因此在两种状态下都拥有全部框架宽度——其几何在轨道与抽屉之间完全不再变化。
- 竖屏唯一入口是**框架自有的浮动按钮**（36x36 控制盒、`IconPanelLeftOutline16`、`layout` 命名空间 `sidebar.open`），停驻在预留的左上角。只要框架是 phone 形态它就保持挂载（稳定 tab 顺序、`aria-expanded` 真实），被它打开的抽屉显示时由 CSS 隐藏，层级为 z-4：高于中心内容，低于中心视图层（z 5，整列视图取代它而不是共享角落），也低于 shell.overlay 层（z 20，模态面板盖住它）。ui-conversation 的头栏在手机形态让出 56px 左侧缺口，面包屑行不会压在控件下面。
- 抽屉／遮罩从 z 26/25 降到 **18/17**，位于 shell.overlay（z 20）之下：从抽屉里打开的全屏面板（设置）必须盖住抽屉，而不是与它分庭抗礼。打开中心视图现在会退出抽屉（与「选择会话退出中心视图」同构），否则抽屉会悬浮在取代该列的视图之上。
- Escape 通过 **capture 阶段** document 监听关闭抽屉：侧边栏抽屉与右侧抽屉同时打开时，一次 Escape 只剥一层（该监听在右侧抽屉的 bubble 阶段处理器之前截停传播），而不是两层一起关。

## Bespoke

无：改动完全骑在既有的形态分级、抽屉 overlay、遮罩与 `narrowExpanded` 开关语义之上。ui-layout 新增对 `@deepseek-ai/dsh-client-ui-primitives` 的 peer 依赖以共享字形（零 cordis 原子包；无需 `inject` 条目）。

## Alternatives considered

- 用 orientation 媒体查询替代宽度形态分级——否决：框架的 `data-viewport` 刻度是客户端唯一断点权威；引入第二个正交分类会让组件看到矛盾状态（窄桌面窗口保有轨道而更窄的手机没有）。
- 入口按钮放进对话头栏——否决：抽屉是框架机制；把控件塞进功能插件会让该插件耦合布局状态，也给未来每个中心视图伸手进布局内部的借口。
- 抽屉打开时保留轨道（旧行为）——放弃：竖屏既然没有轨道就无轨可保，两种状态都持零才是会话栏几何恒定的关键。

## 影响

- 竖屏用户收回整列宽度；侧边栏从轨道一键直达变为两步（入口，再任一侧边栏操作）。
- 竖屏下中心视图会藏起入口（层级所致），离开视图前侧边栏不可达——可接受，因为中心视图自带醒目的关闭。
- 驱动轨道的 e2e 契约（`sidebar(page, 'rail')`）改为驱动抽屉；轨道上的按钮（设置、定时任务）经由抽屉触达，层级修复保证了这一点安全。
