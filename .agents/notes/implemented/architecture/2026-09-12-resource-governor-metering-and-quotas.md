# Agent Note: The resource governor meters shell commands in realm tiers and arbitrates a shared-pool memory quota

Status: implemented

English | [中文](2026-09-12-resource-governor-metering-and-quotas.zh.md)

## Problem

A session's shell commands can execute arbitrary programs, and an agent occasionally runs one that exhausts host memory until the machine freezes; today the only backstop is the container's memory limit, which disappears the day Harniverse runs bare on a host. Nothing in the codebase recorded per-command CPU, memory, disk, or network usage: the pid is born on `SubprocessHandle`, dropped at the shell seam, and never correlated with the session, so neither observation nor enforcement had an anchor. The board feature treats sessions as processes and needs these figures, and a future Rust VM sandbox must plug its own per-VM metrics into the same machinery without a redesign.

## Decision

- **Metering rides the spawn seam.** `SubprocessSpawnSpec` gains an optional `correlation {sessionId, commandId, kind}` plus `limits {maxMemoryBytes}`; the bash tool stamps it from `exec.agent.session`, `LocalBashExecutor` forwards it, and `dsh-subprocess-local` emits `subprocess/spawned` / `subprocess/exited` events carrying it. Only correlated spawns are metered, so LSP servers, subagent providers, and ripgrep stay exempt by default.
- **One `/proc` walk per tick yields three resources.** A single scan of `/proc/*/stat` buckets processes by the metered leader's process group (or POSIX session for PTY), then reads `statm`/`smaps_rollup`/`io` only for bucket members: CPU (utime+stime deltas), memory (RSS/PSS/swap, with anon-versus-file-cache distinction where the cgroup tier provides it), disk (kernel `read_bytes`/`write_bytes`, not syscall rchar/wchar). Network is the only real extra cost: TCP bytes and peer lists are attributed through `ss -tinp` pid matching only when a bucket member owns socket fds, host totals come from `/proc/net/dev`, and UDP and packet-level accuracy are explicitly out of scope. Sampling touches only live metered commands at a configurable base cadence (default 5s, tightening to 1s near limits), with a final read at command exit.
- **Enforcement is tiered by probed capability, never polling-dependent.** Tier C (writable cgroupfs, no systemd assumption): a `dsh/` parent cgroup carries `memory.max` = the global budget, `dsh/<sessionId>/` leaves carry explicit quotas, and the kernel enforces both asynchronously — session quotas cannot pierce the parent, structurally. Tier R (read-only cgroupfs, today's container): non-PTY shell spawns prefix argv with `prlimit --as=` and a sampler watchdog aggregates RSS against the global budget, killing the largest offender and recording the breach. Tier O observes and alerts only. The tier is published through `host.describe`.
- **Quotas are a shared pool with admission control.** The global memory budget defaults to 80% of min(MemTotal, the host's own cgroup ceiling) and is user-configurable in `settings.yaml` under `governor:`; sessions without an explicit quota share the pool (parent cgroup or watchdog protection), explicit quotas are isolation leaves, and an admission check rejects or clamps raises so the sum of committed quotas stays within the global budget. Overrides are durable decisions, not runtime state: the authoritative copy is a governor-owned storage-domain table, every change appends a log-only `governor/quota` audit event to the session log, resume replays the override through admission again (clamping notifies the agent), and `session/disposed` plus a TTL sweep garbage-collect abandoned rows.
- **The `resource-quota` tool lets an agent negotiate only its own session's quota.** The session identity comes from `exec.agent.session`, never from tool arguments; lowering is always allowed, a raise passes admission and — under an ask approval policy — the existing `user-approval` seam (same policy semantics as bash sandbox escalation, so `danger-full-access` never dead-ends the tool). The global budget is unreachable from the model plane; humans adjust it through settings or the administer-gated Remote.
- **Breach outcomes are model-visible, raw samples are not.** When the watchdog or a cgroup OOM kills a command, the bash tool's result meta carries `governor: {killed, peakBytes, limitBytes}` (the output schema widened for exactly this optional field), so the agent can adapt; the sample stream never enters the session log because that log is the model-visible contract. History persistence is opt-in with user-chosen resolution and retention in a storage-domain sidecar table.
- **The board consumes the same door as scripts.** All surfaces are Typert Remote methods on the `governor` namespace with `harniverse.observe`/`operate`/`administer` gating — `overview`, `sessionSamples`, `sessionQuotaGet`/`sessionQuotaAdjust`, `breaches`, `configGet`, `reload` — and the web board polls them; anything the page can do is by construction an HTTP API call. Live samples are pulled, not pushed: the session-projection seam folds events, runtime samples are not events, and the forwarded-event allowlist remains the sanctioned upgrade path to push.
- **The future sandbox plugs in as a realm.** Sample and quota types are transport-neutral and carry a `realmId`; limits travel inside the spawn spec so a sandbox provider can enforce them inside the VM and report metrics against the correlation it echoed. A VM's physical budget is its own global — the host budget does not reach across realms.

## Bespoke

The cgroup tier operates through an injectable filesystem abstraction; on this development container cgroupfs is read-only, so tier C is covered by fake-fs unit tests and bare-metal validation is listed in the package README's Known Limitations. `prlimit` is probed at boot and its absence degrades tier R to watchdog-only. RLIMIT_AS bounds virtual address space, not resident memory — an approximation the README states plainly.

## Alternatives considered

- Per-session cgroups as the only mechanism — rejected: it silently does nothing in containers with read-only cgroupfs and on non-systemd hosts without delegation, which is exactly where the host runs today; the tier probe keeps cgroups as the best tier rather than a hidden single point of failure.
- Enforcement by frequent sampling (watchdog as the only killer) — rejected: polling-based memory enforcement has a latency window proportional to sample cost; the kernel (cgroup OOM) enforces asynchronously at zero polling cost, and the watchdog is the degraded-tier backstop instead of the primary.
- Recording samples as session events for replay — rejected: anything in the session log is model-visible and must reconstruct model requests; resource streams would bloat every context for no model value. Durable samples live in a sidecar domain, opt-in.
- Pushing live metrics through the session-projection channel — dropped: projections are folds over the session event log, and manufacturing pseudo-events to feed them would couple cadence to persistence; Remote polling matches the 5s sample cadence, and the forwarded-events allowlist is the sanctioned push upgrade.
- Attributing network via `/proc/<pid>/net/dev` — rejected after measurement: those counters are network-namespace scoped, identical across processes, so they cannot attribute per command; `ss` socket-diag with pid matching is the accurate-enough baseline, with eBPF or per-VM netns accounting deferred to the sandbox realm where they become structural.

## Consequences

- A runaway command dies at the budget boundary with a truthful reason in the tool result, and the board shows sessions the way `ps` shows processes — CPU, memory, disk, network, quota, and breach history per session.
- Every metered shell spawn pays one prlimit exec prefix on tier R; the walk cost per tick is microseconds per process and zero for idle sessions.
- The machine-level guarantee holds without systemd: the cgroup parent (tier C) or the admission check plus watchdog (tier R) keeps aggregate consumption inside the global budget.
- A future sandbox provider gets metering and quota enforcement by honoring the correlation in the spawn spec and reporting against the shared sample schema; no host-side redesign is required.
- Known limits: UDP traffic and sub-interval short-lived TCP connections are invisible; tier C is untested on real cgroupfs in this environment; Windows relies on a future Job Object provider; the network watchdog alerts but does not kill by default.

## Delivery Follow-ups (2026-09-13)

- **Startup-race fix in `dsh-subprocess-local`.** The original `[Service.init]` prlimit probe (~140ms of real fs I/O) blocked the service start; because `dsh-tool-bash` reads `ctx.shell` lazily, its deferred apply lost the race against the first assembled model request, so compositions that mount the bash tool behind `dsh-subprocess-local` served their first turn WITHOUT the bash tool (reproduced in the ACP snapshot lane). The probe now runs fire-and-forget from the constructor and never blocks start; `prlimitAvailable` stays optimistic until it settles and the `internals` test override still wins at spawn time.
- **Metered-exit pairing is spawn-outcome independent.** `subprocess/spawned` is emitted only for handles that acquired a pid, but the paired `subprocess/exited` (with null exit facts) is now emitted for correlated spawns that fail before acquiring a pid too — metering consumers otherwise leak live-set entries for commands that never started. Terminal twins follow the same shape (node-pty throws synchronously on failure, so a live terminal handle always has a pid).
- **`resource-quota` is preset-scoped, not service-scoped.** The tool moved from the governor service's own registration to a separately loadable `@deepseek-ai/dsh-governor/tool` Consumer entry (`inject: governor, tools`), mounted by the shipped `standard` agent preset; the global tool layer stays empty per the agent-plane architecture and compositions without the governor service leave the row pending. The service exposes `admitExplicit`/`budgetLimitBytes`/`liveRssBytes` as the tool's public seam.
