## Problem

`session_search` 返回的中文片段是损坏的。二元词组折叠是 CJK/假名/谚文子词在 `unicode61` 下获得召回的手段，而折叠后的文本被写入唯一那个已索引的 `text` 列，随后 `highlight()` 又从同一列读回来构造摘录。展示层试图通过删除插入的连接空白来撤销折叠，但这不是重叠二元词组展开的逆运算：`中文字符` 入库为 `中文 文字 字符`，展示为 `中文文字字符`，每个中间字符都翻了一倍。同一次删除也无法区分插入的连接与作者输入的空格，因此 `你好 世界` 展示为 `你好世界`。假名与谚文同时具备这两个缺陷；ASCII 不受影响，这正是测试漏掉它的原因。该损坏是模型可见的：片段是跨会话命中携带的唯一内容。

从折叠文本恢复原文在原理上不可行。长度为一或二的连续串折叠为自身，因此折叠之后，作者输入的空格与二元连接空格是同一位置上的同一字节。

排名还有另一处独立开销。`highlight()` 会把每个候选文档重建为带标记的字符串，再由 SQL `replace` 重新扫描该字符串来数标记，因此每次搜索的耗时正比于所有命中文档的总大小，而不是它返回的那一页。中文文档还要在折叠文本上付出这笔开销，约为其原文的三倍。

## Decision

- **每个文档行在折叠文本旁存储其原文。** `persisted_docs` 与 `temp.live_docs` 新增 `raw_text UNINDEXED`，与 `persisted_titles` 已有的 `raw_title` 伴随列同构。折叠未改变任何内容时 `raw_text` 保持 NULL，因此没有折叠连续串的语料不存第二份副本，读取侧投影 `COALESCE(raw_text, text)`。`codepoint_length` 现在度量原文，使长度平局比较的是文档而非编码——浏览器 fixture 本来就用这个度量。
- **相关性从每张表的 `fts5vocab(..., 'instance')` 伴随表统计已索引词实例数。** 排名读取倒排索引而不是文档：不为打分取回或重扫任何候选。计数在持久表与 TEMP 表之间保持可比，因为两者都是同一批词的原始实例计数——这正是 `bm25()` 无法提供的性质，它的 IDF 与平均文档长度是单表统计量，而 live 表通常只有一两个会话。
- **排名用词来自 SQLite，而不是在 JavaScript 里重新实现 `unicode61`。** 一张分词器配置相同的 TEMP FTS5 表对折叠后查询分词，其 `fts5vocab(..., 'row')` 伴随表给出精确的索引词，包含大小写折叠与变音符号移除(`CAFÉ` → `cafe`、`Straße` → `straße`)。计数连接使用 LEFT JOIN：没有任何已索引词命中的文档排在最后，而不是消失。
- **查询规范化不再把索引编码固化进来。** `normalizeQuery` 返回调用方的空白规范化文本，折叠移到两处 MATCH 构造点，于是片段锚点可以针对原文定位，而请求身份仍是调用方查询的确定性函数。
- **摘录窗口通过在原文中字面搜索折叠词来定位。** 每个折叠词都是其来源原文的字面子串(二元词组跨越连续串中相邻的两个字符)，比较时做小写化与变音符号剥离，并限制每个源字符仍对应一个码点，使折叠位置继续寻址原文。任何更进一步的 `unicode61` 等价关系会锚定到文档开头——先前实现本就把锚点记为近似值。

## Alternatives considered

- **`trigram` 分词器**(保留原文，`highlight()` 天然正确)：按实测否决——两字查询返回空(`压缩` → 0 行、`你好` → 0 行)，而两字词是中文查询的主体。
- **自定义 FTS5 分词器**，把折叠放进分词器内部，是结构上最干净的方案：不可用。`node:sqlite` 的 `DatabaseSync` 未暴露任何 `fts5_api` 注册面。
- **`bm25()` 排名**，实测最快：因其分数在两张表之间不可比而否决，而这一点是包 README 声明的契约。
- **contentless 或外部内容 FTS 表**以避免存储折叠文本：否决。contentless 表丢弃 UNINDEXED 列，元数据列与按会话的 `DELETE` 都要搬到旁表；外部内容会让 `highlight()` 对原文重新分词，而其偏移与折叠索引不再对应。
- **在展示时反转折叠**：如上，不可行。

## Consequences

- 在 1200 文档全中文语料(每篇 600 字、每篇都命中)、同表同数据上实测：两词查询 516 ms → 43 ms，五 token 短语 690 ms → 91 ms，返回载荷降至原先三分之一，因为折叠文本不再离开 SQLite。稀有词查询仍在亚毫秒级。该全中文语料的存储从 6.08 MiB 增至 7.86 MiB(约 29%)，没有折叠连续串的语料不变。
- 片段正文经排名 CTE 携带，而非在 limit 之后连接回来：实测 43 ms 对后置连接的 33 ms。较简单的形态让两种查询范围共用一处投影，也让行到命中的映射不触库；剩下的差值留待更大语料真正需要时再取。
- 相关性统计词实例数，而先前的公式统计合并后的高亮 span 数。两者都是可比的原始计数，在所有构造出的形态(包含多 token 短语)上观察到的顺序完全一致，但在一个已匹配 span 内重复某词的文档现在可能排得略高。
- schema 版本 11 会在首次打开时就地重建每个派生索引。`fts5vocab` 伴随表会出现在 `sqlite_master` 中，因此加入受认可的派生表集合；重置按名称顺序丢弃表，会先到 FTS 表再到其 vocab 伴随表(相反顺序被 SQLite 拒绝)。

## Testing

- `packages/session-query` 322 个测试(此前 318)，改动源文件 per-file 100%。
- 缺陷通过真实装配端到端钉住：`tool-session-query/tests/sqlite-integration.spec.ts` 断言展示的 `Snippet:` 行与原文逐字相等，含中英混排与空格。单测覆盖中文、假名、谚文、作者空格与混合文字；另有测试覆盖窗口锚定、词序、大小写与变音符号折叠、未命中词、组合标记，以及小写化会扩展的字符。
- 既有的可比排名测试与片段长度上界测试原样通过，这是排名契约得以保持的证据。
