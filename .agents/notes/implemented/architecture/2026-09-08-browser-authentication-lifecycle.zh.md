# Agent Note: 共享浏览器认证生命周期与只读状态

Status: implemented

[English](2026-09-08-browser-authentication-lifecycle.md) | 中文

## Problem

浏览器 Cookie 已无法通过新 HTTP 请求的接入校验时，已获准的事件 WebSocket 仍可能继续投递模型分片。将 HTTP 401 当成普通传输异常，会让页面看似已连接而发送失败。单独的续期定时器无法协调前台请求、唤醒竞争、取消和凭据替换。状态渲染器不能成为认证工作的拥有者。

## Decision

[客户端认证能力](../../../../packages/client/authentication/README.md) 为每个页面拥有一个续期运行实例。其 Cordis Service Definition 和 Provider 接管轻量认证入口创建的同一个实例。外壳通过静态模块闭包传递实例，而不是 Loader 配置，因为配置求值处理的是数据，不是存活的类实例。受保护插件仍在认证通过后才加载。启动认证 Provider、模块系统接管配置项与 app-shell 组装是显式的内核基础设施，业务组合仍由 Host 编写。

Connection 通过该能力处理受保护 HTTP 和无法取得状态码的载体恢复。只有 Host 在分发前返回、携带 `x-dsh-authentication: required` 的 401 才允许重试一次；403、结果不确定的写操作、网络异常和一次性请求流都不会自动重放。既有 expected-principal 检查继续生效。并发恢复共享一次交换，调用方取消不会影响其他等待者，迟到失败不能撤回更新后的凭据。Stop 排空交换后，logout 才能清除 Cookie。确定性的认证失败发布刷新说明，不自动刷新页面。

传输存活状态仍由 Connection 拥有。其健康状态可观察源从当前传输状态和认证快照派生稳定的基本值；下行仍打开不能覆盖需要刷新的认证状态。[状态插件](../../../../packages/client/ui-connection-status/README.md) 使用声明注入和框架绑定的可观察钩子，填充侧边栏拥有的 `sidebar.header.status` 根 slot。展开时位于字标与切换按钮之间，收起后的窄栏将只读图标放在合并的标识与切换控件下方。悬停或聚焦说明状态，包括手动刷新提示。图标不拥有网络操作或续期定时器。

本决策部分扩展[公钥 Grant 决策](2026-08-17-public-key-grant-authentication.md)，其中的配对、权限、撤销和凭据边界仍然有效。[WebSocket 载体决策](2026-08-04-websocket-downlink-carrier.md) 保持不变：HTTP 上行和两条只下行事件连接共享一个应用协议。

## Alternatives considered

**每次 401 都自动刷新。** 这会破坏页面局部工作，也掩盖认证是否可恢复、授权是否已撤销。只有自动恢复无法继续时，才明确提示用户刷新。

**让图标执行续期。** 条件渲染、侧边栏收起和插件重载会改变认证生命周期，或者创建重复的续期链。图标只消费服务状态。

**将所有操作移到全双工 WebSocket。** 这会将改动扩大到请求关联、取消和不确定写操作的恢复，却不能消除统一认证拥有者的必要性。

**重试所有失败请求。** 超时或连接丢失不能证明 mutation 尚未执行。Host 在分发前的拒绝才是严格限定的重放依据。

## Consequences

前台请求与连接维护共享认证恢复，不延长凭据寿命，也不弱化 Host 接入校验。新增能力与渲染器分别拥有生命周期，隐藏渲染器不会停止续期。可观察数据不包含凭据。页面外的 Cookie 变化仍在请求或连接检查时发现，页面局部合并不引入跨标签页主节点选举或离线发送队列。

单元测试覆盖续期、共享恢复、取消、终止性拒绝、迟到响应、安全上传重试、拥有者释放和只读渲染。经过正常认证的 Chromium 组合移除有效 Cookie，验证遭拒发送无需导航即可只被接受一次，再撤销 Grant，验证刷新提示及草稿保留。这独立证明了恢复缺陷，并未把原始用户 Cookie 失效的未明触发因素当成已知事实。
